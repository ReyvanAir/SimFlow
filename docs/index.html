SimFlow Documentation

v1.1.0 · UE 5.6

A modular, data-driven task and flow framework for VR simulations, tutorials and procedural gameplay. Author procedures as node graphs; run them from a component; drive your UI from what they report.

    What SimFlow is

    SimFlow runs procedures — an ordered set of things a person has to do, with rules about what happens when they do them wrong, out of order, or not at all.

    You author a procedure as a node graph asset. A component on an actor runs it. Your existing Blueprints feed it events and listen to what it reports.

    Good fit

    • The player must complete steps, and you need to know whether they did
    • Steps have pass/fail conditions, timeouts or scoring
    • The same procedure appears in several scenarios and should be authored once
    • A session might be interrupted and need to resume
    • An instructor needs to skip, retry or fail a step on the trainee's behalf

    Not a fit

    • Cutscenes and camera work — use Sequencer
    • Enemy decision-making — use Behavior Trees
    • Simple one-off triggers — a Level Blueprint is less machinery

    Installing and enabling

    1. Copy the SimFlow folder into YourProject/Plugins/SimFlow.
    2. Right-click the .uproject → Generate Visual Studio project files (or run GenerateProjectFiles).
    3. Build the editor target. SimFlow is a C++ plugin, so the project needs at least one C++ module — if yours is Blueprint-only, add any empty C++ class once from the editor and Unreal converts it.
    4. Enable SimFlow in Edit → Plugins if it is not already on, and restart.
    Two modules

    SimFlowRuntime ships in packaged builds. SimFlowEditor (the graph editor) is stripped on cook. Only node data is packaged, never the visual graph.

    Targets UE 5.6. It also builds on 5.4/5.5 — see Engine compatibility in the developer guide for the one line that may need adjusting.

    Core concepts

    Flow assetThe graph you author (asset type SimFlow Graph). A template, never modified at runtime, so one asset can drive several actors.
    Flow instanceA running copy. Duplicates every node, so each run owns its timers, retry counts and loop counters.
    NodeA box in the graph. Execution arrives at an input pin, the node acts, then pushes out through an output pin.
    TaskThe unit of work inside a Task node. Where the player actually does something. Blueprint-subclassable.
    ConditionA yes/no question about the run. Used by Branch nodes and waiting tasks.
    BlackboardKey/value store for the run: score, mistakes, answers, your own state.
    EventA gameplay tag raised from anywhere. How the world tells the flow something happened.

    Creating your first flow

    Content Browser → right-click → SimFlow → SimFlow Graph. The new asset opens with a Start node already placed.

    1. Right-click empty graph space → Tasks → Task
    2. Drag from Start.Out onto the Task node's In pin
    3. Select the Task node and set Task to one of the built-ins
    4. Expand the Task row — the arrow beside the dropdown — to reach the task's own settings
    5. Right-click → Flow Control → Complete Flow, wire Task.Completed into it
    6. Save

    To run it: add a SimFlow Component to any actor, set Flow Asset, set Start Mode to Auto - On Begin Play, press Play, and type SimFlow.Debug 1 in the console.

    Or skip authoring entirely: Tools → SimFlow → Create Sample VR Tutorial Flow (console: SimFlow.CreateSample) builds a complete example that exercises every feature and opens it.

    The Details panel splits in two

    Time Limit and Auto Retry belong to the node. Display Name, Instruction and Score belong to the task nested inside it. The node owns how the flow treats this step; the task owns what the step is.

    Your own tasks and conditions

    A custom task

    1. Blueprint Class → All Classes → SimFlowTask
    2. In Class Defaults, set Display Name and Instruction
    3. Implement On Task Start — highlight the object, bind a delegate, spawn a marker
    4. Call Finish Task with Succeeded or Failed when the player is done
    5. Implement On Task End to clean up — it runs on skip, fail and abort too, so nothing leaks

    Also available: On Task Tick, On Task Pause, On Task Resume, On Task Retry, On Save Task State, On Load Task State.

    Useful inside a task: Get Blackboard, Get Flow Owner, Get Player Pawn, Set Saved Value / Get Saved Value (survives save/load).

    Tasks cannot reference level actors

    A task lives in the asset, not the level. Find what you need at runtime with Get All Actors With Tag, pass it through the blackboard, or invert the relationship and have the level actor listen to On Task Finished.

    A custom condition

    Blueprint Class → SimFlowCondition, implement Evaluate, return a bool. Invert is applied for you on top of what you return.

    Tutorial UI

    Create a Widget Blueprint, then Graph → Class Settings → Parent Class → SimFlow Status Widget. With Auto Bind on (the default) it binds itself to the primary running flow — or set Flow Save Id to follow a specific one — with no wiring.

    CategoryAvailable
    ReadGet Task Name, Get Instruction, Get Progress, Get Score, Get Time Remaining Text, Get Current Quiz, Is Flow Paused, Can Retry, Can Skip
    Call from buttonsRequest Retry, Request Skip, Request Pause Toggle, Request Restart, Submit Quiz Answer
    Design eventsOn Flow Bound, On Flow Started, On Flow Paused, On Flow Resumed, On Flow Finished, On Task Started, On Task Finished, On Quiz Presented, On Flow State Replicated

    For the quiz, bind On Quiz Presented, read Question and Options off the task, and call Submit Quiz Answer with the index the player picked. In multiplayer it forwards to the server for you.

    Save and load

    Quick Save / Quick Load                    the component's default slot
Save Flow To Slot / Load Flow From Slot    a named slot
Has Save In Slot                           for a "Continue" button
Save All Flows / Load All Flows            every flow in the game at once (statics)

    A save holds the blackboard, every node's state, elapsed time, raised events and the last checkpoint.

    ModeBehaviour
    Exact StateEvery active node comes back active with its elapsed time and retry count. Tasks re-run On Task Start, so world setup is reapplied.
    From Last CheckpointRestores the blackboard, then resumes from the last Checkpoint passed. More forgiving, usually better for an interrupted VR session.

    Several flows share one slot, keyed by the component's Flow Save Id. Turn on Auto Resume From Save On Begin Play to pick a save up automatically when one exists.

    Object references are not saved

    Re-resolve them in On Load Task State, or look the actor up again by tag.

    Multiplayer

    Off by default. The server runs everything; clients mirror. Your existing Blueprint calls work unchanged — they detect they are on a client and forward to the server.

    1. Put the component on a replicated actor — Game State for a shared scenario, Player State for one flow per trainee
    2. Tick Replicate Flow
    3. Add a SimFlow Player Component to your PlayerController Blueprint
    Step 3 is the non-obvious one

    A flow on the Game State has no owning connection, so a client cannot RPC it directly. The player component sits on the PlayerController — which always has one — and relays requests. Without it, clients can watch but not act, and you get a warning in the log.

    Client-safe calls (they forward themselves): Start/Stop/Restart, Pause/Resume/Toggle Pause, Retry/Skip/Fail Current Task, Send Event, Submit Quiz Answer, Broadcast Flow Event, Request Flow Control.

    Save and load are server-only. On a client they log a warning and do nothing. Get Current Task() on a client returns the authored template task — its text is right, its runtime counters are not; read those from Get Net State.

    Debugging

    SimFlow.Debug 1 in the console shows flow name, run state, elapsed time, progress, every active node with its countdown and retry count, and the whole blackboard. Per-component, tick Show Debug HUD.

    For VR, Get Debug Text returns the same text as a string — put it on a world-space widget so you can read it in the headset.

    Output Log, filtered to LogSimFlow, records every task start, finish, retry and refusal, plus warnings for misconfiguration.

    The Validation panel in the graph editor refreshes on every edit and reports missing tasks, dead ends, unreachable nodes and dangling links.

    Object model

    USimFlowAsset                 the authored template
  └─ TArray<USimFlowNode*>    outered to the asset, survives cooking
       ├─ USimFlowTask        Instanced sub-object on Task nodes
       └─ USimFlowCondition   Instanced sub-object where used

USimFlowComponent             on an actor
  └─ USimFlowInstance         a running copy
       ├─ duplicated nodes    DuplicateObject of every template node
       └─ USimFlowBlackboard

    The template/instance split is the central design decision. USimFlowAsset is never mutated at runtime; BuildRuntimeNodes duplicates every node so each run owns its timers, retry counts and loop counters. Two actors can run the same asset, and Sub Flow nests instances (with an optional parent-child blackboard copy both ways).

    Node identity is FGuid NodeGuid, preserved across duplication. Links, save data and replication all address nodes by Guid rather than pointer.

    Execution model

    Execution is queue driven, not recursive. TriggerNodeOutput enqueues targets rather than calling into them; ProcessPendingActivations drains the queue under a re-entrancy guard.

    void USimFlowInstance::ProcessPendingActivations()
{
    if (bProcessingActivations) return;      // re-entrancy guard
    bProcessingActivations = true;

    while (PendingActivations.Num() > 0 && RunState == ESimFlowRunState::Running)
    {
        if (++Processed > MaxActivationsPerProcess) { bOverflowed = true; break; }
        const FPendingActivation Next = PendingActivations[0];
        PendingActivations.RemoveAt(0, 1, EAllowShrinking::No);
        if (USimFlowNode* Node = FindRuntimeNode(Next.NodeGuid))
            ActivateNode(Node, Next.InputPin);
    }

    bProcessingActivations = false;
    if (bOverflowed) { /* log, fail the flow */ }
}
    • A chain of a thousand instant nodes costs one stack frame, not a thousand
    • A runaway loop is caught at MaxActivationsPerProcess = 10,000 activations per step and fails the flow with an error rather than hanging the editor
    • Ordering stays breadth-first within a step

    ActivateNode refuses to re-enter an already-active node unless it overrides AllowsReentrantActivation(). Join and Loop do; nothing else does.

    Dead ends: if a node deactivates with no links and nothing else is active or queued, the instance completes the flow. That is what lets an unwired Completed pin end a simple flow cleanly.

    Pins and links

    USTRUCT() struct FSimFlowPinLink   { FGuid NodeGuid; FName PinName; };
USTRUCT() struct FSimFlowOutputPin { FName PinName; FString DisplayName;
                                     TArray<FSimFlowPinLink> Links; };
USTRUCT() struct FSimFlowInputPin  { FName PinName; FString DisplayName; };

    Nodes store their own pins and outgoing links. The editor graph is a view — on every change, USimFlowGraph::CompileToAsset clears all links and rebuilds them from the visual connections. The runtime never reads the UEdGraph.

    Well-known names live in namespace SimFlowPins: In, Out, Completed, Failed, Skipped, TimedOut, Default, LoopBody. Use them rather than string literals. (Loop's Continue pin is USimFlowNode_Loop::ContinuePin.)

    Rebuilding pins

    RebuildPins() is non-virtual and follows a template method pattern: stash existing links, clear the arrays, call the virtual BuildPins(), restore links onto any pin whose name still exists. Override BuildPins(), never RebuildPins().

    void USimFlowNode_Task::BuildPins()
{
    AddInputPin(SimFlowPins::In);
    AddOutputPin(SimFlowPins::Completed);
    AddOutputPin(SimFlowPins::Failed);
    AddOutputPin(SimFlowPins::Skipped);
    AddOutputPin(SimFlowPins::TimedOut);
}

    Because links are preserved by name, changing a Branch's case count keeps the wires on cases that still exist.

    Menu labels come from the CDO

    GetNodeCategory() places the node in the right-click menu, and the label is the class default object's GetNodeTitle(). That is why the Finish node lists as "Complete Flow".

    Task lifecycle

    USimFlowNode_Task owns a USimFlowTask as an Instanced sub-object and drives it. C++ overrides are NativeTaskStart/Tick/Pause/Resume/End; Blueprint gets ReceiveTaskStart and friends. Both fire — native first.

    ExecuteInput      → InitializeTask → StartTask → NativeTaskStart, ReceiveTaskStart
TickNode          → TickTask → NativeTaskTick, ReceiveTaskTick
                  → abort condition checked
                  → time limit checked
FinishTask(Result)→ score applied → NativeTaskEnd, ReceiveTaskEnd
                  → OnTaskFinished broadcast
                  → OwningNode->HandleTaskFinished(Result)

    HandleTaskFinished applies auto-retry if configured, then maps the result to a pin. With bFallbackToCompleted, an unwired Failed/Skipped/TimedOut pin falls through to Completed.

    FinishTask is guarded by bFinishRequested, so calling it twice in one activation is harmless. Runtime read-only fields on the task: bIsRunning, bIsPaused, ElapsedTime, RetryCount, FlowInstance, OwningNode.

    Writing a custom node

    UCLASS(DisplayName = "Wait For Actor Tag")
class MYGAME_API USimFlowNode_WaitForActorTag : public USimFlowNode
{
    GENERATED_BODY()
public:
    USimFlowNode_WaitForActorTag() { RebuildPins(); }

    UPROPERTY(EditAnywhere, Category = "Wait")
    FName ActorTag;

    virtual void BuildPins() override
    {
        AddInputPin(SimFlowPins::In);
        AddOutputPin(SimFlowPins::Out);
    }

    virtual void ExecuteInput(FName PinName) override
    {
        ActiveTime = 0.f;   // stay active; TickNode does the work
    }

    virtual void TickNode(float DeltaTime) override
    {
        Super::TickNode(DeltaTime);
        if (/* found */) TriggerOutput(SimFlowPins::Out);
    }

    virtual FText GetNodeCategory() const override
    {
        return NSLOCTEXT("MyGame", "Cat", "My Game");
    }
};

    Call RebuildPins() in the constructor — the virtual dispatches correctly there because the derived constructor body is running.

    The node appears in the graph menu automatically: the schema iterates every non-abstract USimFlowNode subclass whose CDO returns true from IsPlaceableInGraph().

    Custom tasks and conditions

    UCLASS(DisplayName = "Hold Trigger")
class MYGAME_API USimFlowTask_HoldTrigger : public USimFlowTask
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, Category = "Hold")
    float RequiredSeconds = 2.f;

    virtual void NativeTaskStart() override { Held = 0.f; }

    virtual void NativeTaskTick(float DeltaTime) override
    {
        Held = IsTriggerHeld() ? Held + DeltaTime : 0.f;
        if (Held >= RequiredSeconds) FinishTask(ESimFlowResult::Succeeded);
    }

    virtual void NativeTaskEnd(ESimFlowResult Result) override { /* unbind */ }

private:
    float Held = 0.f;
};

    Conditions override NativeEvaluate(USimFlowInstance*) const. Evaluate is non-const, applies bInvert, and lets a Blueprint ReceiveEvaluate override the native result. Override GetConditionDescription_Implementation() for the label shown on graph nodes and in the HUD.

    Both USimFlowTask and USimFlowCondition are Abstract, Blueprintable, EditInlineNew, DefaultToInstanced, CollapseCategories, so they appear as inline configurable objects in the Details panel.

    Blackboard and FSimFlowValue

    FSimFlowValue is a tagged union over Bool / Int / Float / String / Name / Vector / Object, kept as a plain USTRUCT so it survives SaveGame serialisation and replicates without a custom NetSerialize.

    FSimFlowValue::MakeFloat(12.5f);
Value.AsNumber();   // best-effort numeric (bool -> 0/1, string -> Atof)
Value.AsBool();
Value.AsString();
Value.Compare(ESimFlowCompareOp::GreaterOrEqual, Other);
Value.Add(Other);                // numbers, strings, vectors
Value.StripObjectReferences();   // before saving

    USimFlowBlackboard::ToEntries(bStrip) flattens the map to TArray<FSimFlowBlackboardEntry> for saving and replication, dropping object values. FromEntries restores; MergeFrom is what Sub Flow uses to copy a blackboard in and out.

    Typed accessors (GetFloat, SetVector, …) and score helpers (AddScore, GetScore) are all Blueprint-exposed. OnValueChanged(Key, NewValue) fires on every write — the component listens to it to mark the replicated blackboard dirty.

    Object references are deliberately not persisted — a raw pointer has no meaning across a save or a network boundary.

    Exact State restores by activating each node that was active, then calling LoadNodeState — activate first so the task runs its start logic and reapplies world setup, then overwrite the counters. From Last Checkpoint restores the blackboard and re-enters the checkpoint node.

    Replication

    Off unless bReplicateFlow. Server-authoritative with client mirroring.

    UPROPERTY(ReplicatedUsing = OnRep_NetState)
FSimFlowNetState NetState;

UPROPERTY(ReplicatedUsing = OnRep_Blackboard)
TArray<FSimFlowBlackboardEntry> ReplicatedBlackboard;   // gated by bReplicateBlackboard

    FSimFlowNetState carries run state, active node Guids, an FSimFlowNetTask per active task (Guid, start server time, time limit, retry count), progress, elapsed time and bHasEverStarted. Nodes, tasks and conditions never replicate. Clients already have the flow asset, so they resolve a Guid back to the authored node and read display names, instructions and quiz content locally. Bandwidth is flat with respect to graph size.

    UpdateNetState compares with EqualsIgnoringTime so elapsed time alone does not dirty the state every frame; a periodic refresh (NetRefreshInterval) keeps it from going stale.

    Authority gating

    bool HasFlowAuthority() const
{
    if (!bReplicateFlow) return true;              // single player: everyone
    const AActor* Owner = GetOwner();
    return !Owner || Owner->HasAuthority();
}

    TickComponent early-outs on a mirror. Control functions check IsClientMirror() and forward to the server through the local USimFlowPlayerComponent.

    Presentation events go out as NetMulticast, Reliable RPCs carrying a node Guid. ShouldMulticastEvents() decides between multicasting and firing locally, so standalone and dedicated-server paths both fire each delegate exactly once.

    Client → server control. A flow on the Game State has no owning connection, so USimFlowPlayerComponent lives on the PlayerController and relays requests (ServerRequestControl / ServerRequestQuizAnswer / ServerRequestEvent), resolving the target by Flow Save Id. Every request passes IsRequestAuthorised(TargetFlow, Request) server-side — a BlueprintNativeEvent you override for instructor-only controls. bRestrictToOwnedFlows is the built-in default gate.

    Engine compatibility

    Targets 5.6, and builds on 5.4/5.5. One line needs to match the engine. FEdGraphSchemaAction::PerformAction's location parameter has moved between FVector2D and the FVector2f-backed UE::Slate::FDeprecateVector2DParameter, and it cannot be inferred from the version number. SimFlowEditorCompat.h deduces the type from the base class declaration rather than hardcoding it.

    // SimFlowEditorCompat.h
#define SIMFLOW_PERFORMACTION_LOCATION_MODE 0
//  0  const FVector2D                                 (verified on UE 5.6)
//  1  const UE::Slate::FDeprecateVector2DParameter&
//  2  const UE::Slate::FDeprecateVector2DParameter

    A wrong setting fails loudly: "method with override specifier 'override' did not override any base class methods". Check Engine/Source/Runtime/Engine/Classes/EdGraph/EdGraphSchema.h, find the PerformAction overload taking a single UEdGraphPin* FromPin, and match its third parameter.

    Logging and diagnostics

    LogSimFlow (runtime) and LogSimFlowEditor (editor). Module startup logs at Display so it shows without changing verbosity.

    SimFlow.Debug 1        on-screen overlay for every running flow
SimFlow.Debug 0        off
SimFlow.CreateSample   build the sample flow asset (editor)

    USimFlowAsset::ValidateFlow(OutErrors, OutWarnings) is public and Blueprint-callable — reachable from commandlets and automation, not just the editor panel. It reports missing Start nodes, dangling links, task nodes with no task, unreachable nodes and nodes with no outgoing connections.

    Known limitations

    LimitationDetail
    Join Wait For Any leaves the loser runningThe node stays alive to swallow the late arrival so downstream cannot fire twice, but the losing branch's task continues until the flow ends
    Blackboard replication resends the whole arrayFine for tens of keys at tutorial pacing; move to a FastArraySerializer beyond that
    Presentation multicasts are reliableAppropriate for a flow that changes task every few seconds, not for high-frequency events
    Object values are neither saved nor replicatedBy design — resolve actors at runtime
    Custom nodes require C++Tasks and conditions do not
    Tasks cannot reference level actorsThey live in the asset. Resolve by tag, pass through the blackboard, or invert to a delegate listener
    A task with no time limit and no other exit hangs silentlyNo error, no log line. ValidateFlow does not catch it — it is a runtime condition, not a graph-structure one
    An unconfigured Wait For Event succeeds immediatelyIt logs a warning, but a silent success is arguably the wrong default
