SimFlow 1.1.5 · UE 5.6 and 5.8

SimFlow User Guide

Build simulation and training procedures as node graphs, run them on an actor component, and drive your UI from what the run reports. This guide is written for the people who author scenarios: technical designers, level designers and simulation engineers.

What this guide assumes

That you are comfortable in the Unreal editor and in Blueprint, and that you have never seen SimFlow before. No C++ is required anywhere in these seven chapters. The plugin itself is C++, which means your project needs a C++ module to compile it, and that is the only engineering prerequisite.

Every claim here is against SimFlow 1.1.5. Where a capability does not exist in this version, the guide says so plainly and gives the pattern people actually use instead, rather than describing a field that is not in the Details panel.

Fastest possible start

  1. Install and build. Chapter 01
  2. Run Tools → SimFlow → Create Sample VR Tutorial Flow and read it top to bottom.
  3. Build the three-node hello flow. Chapter 01
  4. Turn on SimFlow.Debug 1 and leave it on.

Graph node and task reference

Every node and every built-in task has its own page: the full field table with types and shipped defaults, what each pin does, how the thing decides what it decides, a worked example, and the failure modes with their causes. Chapter 03 is the tour; these are the pages you keep open while building.

Everything in the two tables below goes inside a flow asset. The nodes SimFlow adds to ordinary Blueprint graphs are a separate set, in the Blueprint node reference further down.

Nodes · where execution goes
NodeWhat it does

BranchCondition-based routing, evaluated top to bottom.

ParallelFires every wired output at once.
JoinConverges branches. Wait for all, or race.

Reading order

If you are new, read Task first. It is the node you will place most, and it owns the timeout and retry behaviour every task inherits.

After that, Branch and Finish cover routing and ending a run, which between them account for most of the questions people ask in the first week.

Place Object In Zone and Ordered Sequence are the two worth reading in full even if you do not need them yet. They are where object identity, match quality and the mistake policies all come together, and understanding one of them explains most of the others.

The three components

SimFlow adds three actor components, and a project usually needs one or two of them. One runs the procedure, one tells the procedure what an object is, and one lets a client press a button in multiplayer. Each page covers what it does, where it goes, when you need it, and its Details panel field by field.

Components · 3 pages

SimFlow ComponentA level actor, Game Mode, Game State or PlayerStateAlways. Nothing runs a flow without it.
SimFlow IdentityThe item BlueprintA task has to recognise an object by what it is, not by which actor it is.

Start with the first one

SimFlow Component is the class you touch every day: start and pause, the eleven dispatchers your UI binds to, saving, and the replication switch. The other two are answers to specific problems.

Start with the object model

Template against instance is the decision everything else follows from. Nodes are duplicated per run and addressed by FGuid, which is why links, saves and replication all work the way they do. Read that section before the others and the rest falls into place.

Conventions used here

Callout types

A note in blue adds context you can act on. An amber warning marks a setting that commonly produces wrong behaviour. A red trap marks something that fails silently, which in this plugin is the category that costs the most time.

Field tables

Parameter tables list the field name, its type, the shipped default and what it does. Defaults matter more than usual in SimFlow, because several of them (Fallback To Completed on, Score On Success at zero, Time Limit at zero) decide behaviour that people then spend an afternoon debugging.
