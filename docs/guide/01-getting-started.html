Chapter 01

Getting Started and Installation

Get SimFlow into a project on Unreal Engine 5.6 or 5.8, confirm the editor module actually loaded, and prove it end to end with a three-node flow running on a test actor. Budget about twenty minutes including the build.

Naming

If you arrived from a procedure-training spec, the vocabulary maps like this: a Procedure Graph Asset is a SimFlow Graph asset, and a Procedure Component is the SimFlow Component (USimFlowComponent). Those are the names you will see in the editor and in Blueprint.

Before you install

SimFlow ships as two C++ modules, SimFlowRuntime and SimFlowEditor. That produces exactly one hard prerequisite, and it is the one that catches most people on the first attempt:

Your project needs a C++ module

A Blueprint-only project cannot compile the plugin, so the editor offers you nothing in the Content Browser and gives no obvious reason why. Fix it once: Tools → New C++ Class → None, create any empty class, and let Unreal convert the project. You never have to write C++ after that. Everything in this guide is Blueprint and the Details panel.

What you need before starting
RequirementWhy
UE 5.6 or 5.8The shipped descriptor targets 5.8.0. See engine versions for the 5.6 path.
A C++ projectBoth plugin modules compile from source with your project.
A configured compilerVisual Studio with the Game Development with C++ workload on Windows, Xcode on macOS.
GameplayTagsAn engine plugin, on by default. SimFlow uses gameplay tags for identity and for events.

Install into the project Plugins directory

This is the supported path and the one to use unless you have a specific reason not to. The plugin lives with the project, gets versioned with the project, and compiles against the exact engine the project uses.

  1. Copy the plugin folder

    Place the SimFlow folder at YourProject/Plugins/SimFlow. The SimFlow.uplugin file must sit directly inside it, not one level deeper.

    Check: YourProject/Plugins/SimFlow/SimFlow.uplugin should exist, alongside Source/ and Resources/.

  2. Regenerate project files

    Right-click the .uproject and choose Generate Visual Studio project files. On macOS or from a terminal, run the engine's GenerateProjectFiles script against the project.

  3. Build the editor target

    Build YourProjectEditor in the Development Editor configuration, with the editor closed. A first build of both modules takes a few minutes.

    If the build fails here, read the first error rather than the last. A missing GameplayTags dependency in your own module and a stale Intermediate folder are the two usual causes. Deleting Binaries/ and Intermediate/ then regenerating clears the second.

  4. Open the project

    Launch from your IDE, or open the .uproject. If Unreal offers to rebuild missing modules, accept.

Unreal Engine 5.6 and 5.8

The descriptor that ships with 1.1.5 declares 5.8.0:

"VersionName": "1.1.5",
"EngineVersion": "5.8.0",
"Modules": [
  { "Name": "SimFlowRuntime", "Type": "Runtime", "LoadingPhase": "PreDefault" },
  { "Name": "SimFlowEditor",  "Type": "Editor",  "LoadingPhase": "Default" }
]

Because the plugin is distributed as source and compiles with your project, targeting 5.6 is a descriptor edit plus a rebuild. Open SimFlow.uplugin, set "EngineVersion": "5.6.0", regenerate project files, and build.

Verify rather than assume. If a module fails to compile on 5.6, expect it to be SimFlowEditor: editor and graph-editor API shifts more between releases than runtime API does. The runtime module is the one that matters at ship time, so a 5.6 port that stalls is usually a small number of editor-side call sites.

Per-version checklist

  • Set EngineVersion to match the engine you are opening with.
  • Regenerate project files after every descriptor change.
  • Delete Binaries/ and Intermediate/ when moving a project between engine versions.
  • Build with the editor closed.
  • Confirm both modules loaded before debugging anything else. See Verify the install.

Marketplace and engine-level installs

The plugin descriptor ships with an empty MarketplaceURL, so there is no store listing wired into this build. Treat the project Plugins directory as the canonical install route.

If your studio distributes SimFlow as a prebuilt binary through Fab, the Epic Games Launcher or an internal package, the rules are the standard engine-plugin ones:

Install locations and what each implies
LocationPathImplication
Project (recommended) YourProject/Plugins/SimFlow Compiles from source with the project. Versioned in your repo. Works on any engine version you can build against.
Engine, launcher-installed Engine/Plugins/Marketplace/SimFlow Shared by every project on that engine install. The binary is built for one engine version only, so a 5.8 package will not load in 5.6.
Engine, source build Engine/Plugins/SimFlow For teams on a custom engine. Rebuilt whenever the engine is.
Do not install in both places

A project copy and an engine copy of the same plugin conflict, and the error names a duplicate plugin rather than the real problem. Pick one location per machine.

Enable SimFlow in Edit → Plugins

A project-directory install is usually enabled automatically on first load. Confirm it anyway, because the rest of this chapter depends on it.

  1. Open the plugin browser

    Edit → Plugins, then search for SimFlow. It appears under the Gameplay category.

  2. Tick Enabled

    If the checkbox is already ticked, leave it. If you tick it now, Unreal asks to restart. Accept.

    If SimFlow is not listed at all, the modules did not build. Go back to step 3 and read the build output. An unlisted plugin is a build problem, never a settings problem.

  3. Confirm the version

    The entry should read version 1.1.5. That confirms the editor is reading the descriptor you think it is, which matters when a stale copy is sitting in an engine directory.

Verify the install

Two checks, thirty seconds. Do both before building anything.

Check 1: the editor module

Right-click empty space in the Content Browser. A SimFlow section containing SimFlow Graph means the editor module loaded and registered its asset type.

No section means the runtime module may have loaded while the editor module did not. Check the Output Log for SimFlowEditor at startup.

Check 2: the sample flow

Run Tools → SimFlow → Create Sample VR Tutorial Flow. It generates a complete flow that exercises most of the plugin and opens it for you.

This is the fastest way to see nodes, tasks and conditions working together, and it is a better first read than any diagram. Open it, read it top to bottom, then come back and build your own.

Build your first flow

Three nodes. The point is not the flow, it is confirming that authoring, execution and output all work on your machine.

  1. Create the asset

    Content Browser → right-click → SimFlow → SimFlow Graph. Name it F_HelloFlow and open it. A Start node is already in the graph. Every flow needs one, and it is where execution begins.

  2. Add a Task node

    Right-click the graph, choose Tasks → Task, then drag from the Start node's Out pin onto the new node's In pin.

  3. Assign a task to it

    Select the Task node. In the Details panel find the Task field, open the dropdown and choose Log Message. The field expands to show that task's own settings inline. Set Message to Hello from SimFlow.

    One thing to know before you hit Play: a Task node with an empty Task slot does not fail. It logs a warning and passes straight out of Completed. That is deliberate, so a half-built flow still runs end to end, and it is also why a forgotten task slot can look like success.

  4. Terminate the flow

    Right-click, choose Flow Control → Finish, and wire the Task node's Completed pin into the Finish node's In pin. Save the asset.

Attach the component and run it

  1. Pick a host actor

    For this test, anything works. The Game Mode, a level actor or your VR pawn are all valid. Chapter 05 covers which to choose for real work, and why it matters once replication is involved.

  2. Add the component

    Add Component → SimFlow Component. In its Details panel set Flow Asset to F_HelloFlow.

  3. Set Start Mode to Auto - On First Tick

    Not On Begin Play. On BeginPlay, other actors in the level may not have begun play yet, so a flow that immediately looks for a zone or an item can fail to find it. By the first tick every actor has begun play.

  4. Press Play

    Hello from SimFlow prints on screen. If it does not, go to the checklist below.

Turn on the debug overlay

Open the console with the tilde key and enter:

SimFlow.Debug 1

Live flow state draws on screen: the active node, the current task, elapsed time and the whole blackboard. This is the most useful debugging tool in the plugin, and most reports of "it does not work" are answered by seeing which node is actually active. SimFlow.Debug 0 turns it off. For one flow rather than all of them, tick Show Debug HUD on the component.

Make it react to the world

A flow that prints a message proves the pipeline. The next step proves the part you will actually use: the flow waiting for the trainee to do something.

  1. Swap the task

    Select the Task node and change Task to Wait For Event. Set Event Tag to SimFlow.Event.Interact. The flow now blocks at that node until something raises the tag.

  2. Raise the event from a Blueprint

    In any actor Blueprint (a button, a grabbable prop, an animation notify), call Broadcast Flow Event with Event Tag set to SimFlow.Event.Interact and Payload set to self.

  3. Play and trigger it

    The flow advances past the Task node and reaches Finish.

Broadcast from the actor, never from a widget

Passing self from inside a UMG widget graph is the most common first bug in the whole plugin. A UUserWidget is neither an Actor nor an Actor Component, so it can never satisfy a payload check. It scores No Match and logs a warning naming the offending class. Broadcast from the actor that owns the widget instead.

If something did not work

Install and first-run symptoms
SymptomCauseFix
No SimFlow entry in the Content Browser right-click menu The editor module did not build or did not load Rebuild the editor target with the editor closed. Check the Output Log at startup for SimFlowEditor.
SimFlow is missing from Edit → Plugins The descriptor is not where Unreal looks, or the build failed Confirm YourProject/Plugins/SimFlow/SimFlow.uplugin, then regenerate project files.
Build fails immediately on a Blueprint-only project No C++ module to compile the plugin into Add any empty C++ class once, then regenerate and build.
Nothing prints on Play Usually Flow Asset unset, Start Mode left on Manual, or the Start node's Out pin unwired Run SimFlow.Debug 1 and look at which node is active. An unwired pin ends execution without a word.
The flow starts, then cannot find zones or props Start Mode is Auto - On Begin Play Switch to Auto - On First Tick.
Events never reach the flow Broadcasting from a widget, or a tag mismatch Broadcast from the owning actor. Filter the Output Log by LogSimFlow.

Everything above logs under the LogSimFlow category. Filter the Output Log by it before guessing. Chapter 07 covers the silent failures, which are the ones that log nothing at all.
