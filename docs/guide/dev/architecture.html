Architecture and Modules

Modules
SimFlowRuntime (PreDefault), SimFlowEditor (Default)
Ships in builds
Runtime only. The editor module is stripped on cook.
Central decision
Template against instance. The asset is never mutated at runtime.

Read this first. Everything else in the developer guide assumes the object model below, particularly the fact that nodes are duplicated per run and addressed by FGuid rather than by pointer.

Module dependencies
ModuleDepends on
SimFlowRuntime Public: Core, CoreUObject, Engine, GameplayTags, DeveloperSettings, UMG, SlateCore, NetCore. Private: Slate, InputCore, Projects, plus UnrealEd in editor builds.
SimFlowEditor Adds UnrealEd, EditorFramework, EditorSubsystem, ToolMenus, GraphEditor, KismetWidgets, PropertyEditor, AssetDefinition, AssetTools, ApplicationCore, WorkspaceMenuStructure.
GameplayTags is a module, not a plugin

It must not appear in the .uplugin file's Plugins array. Unreal will go looking for a GameplayTags.uplugin that does not exist and refuse to load the whole plugin. It belongs in the .Build.cs dependency list and nowhere else.

Object model

USimFlowAsset                      the authored template
  └─ TArray<USimFlowNode*>         outered to the asset, survives cooking
       ├─ USimFlowTask             Instanced sub-object on Task nodes
       └─ USimFlowCondition        Instanced sub-object wherever used

USimFlowComponent                  on an actor
  └─ USimFlowInstance              a running copy
       ├─ duplicated nodes         DuplicateObject of every template node
       └─ USimFlowBlackboard

The template and instance split is the central design decision. USimFlowAsset is never mutated at runtime. BuildRuntimeNodes duplicates every node so each run owns its own timers, retry counts and loop counters. Two actors can run the same asset without interfering, and Sub Flow nests instances with an optional parent and child blackboard copy in both directions.

Nodes are addressed by Guid, never by pointer

FGuid NodeGuid is preserved across duplication. Links, save data and replication all resolve a node through FindRuntimeNode(Guid). That is what lets a client hold only the asset and still know which node the server means.

Why nodes are outered to the asset

Runtime nodes live under the asset rather than under the UEdGraph, because the graph is editor-only and gets stripped on cook. A node outered to the graph would vanish from a packaged build. The editor module covers the copy and paste re-parenting dance this forces.

Engine compatibility

The plugin targets 5.8 and builds on 5.4 through 5.6. One type has to match the engine, and the header works it out for you.

FEdGraphSchemaAction::PerformAction's location parameter moved from FVector2D to FVector2f partway through the 5.x line. SimFlowEditorCompat.h picks by version, so an ordinary build needs no setup:

// SimFlowEditorCompat.h
#if UE_VERSION_OLDER_THAN(5, 6, 0)
    #define SIMFLOW_PERFORMACTION_LOCATION_MODE 0   // const FVector2D
#else
    #define SIMFLOW_PERFORMACTION_LOCATION_MODE 3   // const FVector2f&
#endif

5.4 declares only the FVector2D overload. 5.6 added the FVector2f& one and stamped UE_DEPRECATED(5.6) on the old one, and 5.8 has not changed that — which is where the cut comes from. Mode 0 on a newer engine does compile, because the engine's FVector2f& overload forwards to the deprecated one, but every override warns, and a target that promotes those warnings to errors will not build. Fab submission is one of those targets.

To force a mode from SimFlowEditor.Build.cs, use PublicDefinitions:

PublicDefinitions.Add("SIMFLOW_PERFORMACTION_LOCATION_MODE=3");

PrivateDefinitions will not do. The chosen type ends up in the PerformAction signature of exported structs in the public header SimFlowGraphSchema.h, so a define that reaches only SimFlowEditor leaves every other module compiling a different signature — a link error, or an override quietly bound to the wrong base function.

A wrong setting fails loudly, which is the good case

If you ever see "method with override specifier 'override' did not override any base class methods", the version guard guessed wrong for your engine. Open Engine/Source/Runtime/Engine/Classes/EdGraph/EdGraphSchema.h, find the PerformAction overload taking a single UEdGraphPin* FromPin, match its third parameter, and force that mode from your Build.cs.
