Developer Guide

Custom Tasks and Conditions

Base classes
USimFlowTask, USimFlowCondition
Class flags
Abstract, Blueprintable, EditInlineNew, DefaultToInstanced, CollapseCategories
Language
C++ or Blueprint. Both work.

This is the extension point you will reach for most. Those class flags are what make a task appear as an inline, configurable object in the Details panel rather than as a separate asset to create and wire up.

The task lifecycle

USimFlowNode_Task owns a USimFlowTask as an Instanced sub-object and drives it. C++ overrides are NativeTaskStart, NativeTaskTick, NativeTaskPause, NativeTaskResume and NativeTaskEnd. Blueprint gets ReceiveTaskStart and friends. Both fire, native first.

ExecuteInput      → InitializeTask → StartTask → NativeTaskStart, ReceiveTaskStart
TickNode          → TickTask → NativeTaskTick, ReceiveTaskTick
                  → abort condition checked
                  → time limit checked
FinishTask(Result)→ score applied → NativeTaskEnd, ReceiveTaskEnd
                  → OnTaskFinished broadcast
                  → OwningNode->HandleTaskFinished(Result)

HandleTaskFinished applies auto-retry if the node is configured for it, then maps the result to a pin. With bFallbackToCompleted, an unwired Failed, Skipped or TimedOut pin falls through to Completed.

FinishTask is safe to call twice

It is guarded by bFinishRequested, so a double-fire from an event binding does no harm. You do not need to defend against it in your own code.

Read-only runtime fields available on the task while it runs: bIsRunning, bIsPaused, ElapsedTime, RetryCount, FlowInstance, OwningNode.

A custom task

UCLASS(DisplayName = "Hold Trigger")
class MYGAME_API USimFlowTask_HoldTrigger : public USimFlowTask
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, Category = "Hold")
    float RequiredSeconds = 2.f;

    virtual void NativeTaskStart() override { Held = 0.f; }

    virtual void NativeTaskTick(float DeltaTime) override
    {
        Held = IsTriggerHeld() ? Held + DeltaTime : 0.f;
        if (Held >= RequiredSeconds) FinishTask(ESimFlowResult::Succeeded);
    }

    virtual void NativeTaskEnd(ESimFlowResult Result) override { /* unbind */ }

private:
    float Held = 0.f;
};

The class appears in the Task dropdown on its own, with RequiredSeconds inline underneath. Retry, skip, timeout, pause and scoring all come from the Task node without you implementing any of it.

The same thing in Blueprint

  1. Create the class

    Blueprint Class from SimFlow Task.

  2. Set up in On Task Start

    Override On Task Start. Bind whatever you need to listen to.

  3. Finish with a result

    Call Finish Task with Succeeded or Failed when the work is done.

  4. Clean up in On Task End

    Unbind everything you bound. This fires however the task ended, including a timeout or an abort.

    Use Set Saved Value and Get Saved Value for state that has to survive a save and reload. They write into FSimFlowNodeSaveState::CustomData for you.

Conditions

Conditions override NativeEvaluate(USimFlowInstance*) const. Evaluate is non-const, applies bInvert, and lets a Blueprint ReceiveEvaluate override the native result.

UCLASS(DisplayName = "Player Is Crouching")
class MYGAME_API USimFlowCondition_Crouching : public USimFlowCondition
{
    GENERATED_BODY()
public:
    virtual bool NativeEvaluate(USimFlowInstance* Instance) const override
    {
        const APawn* P = /* resolve from Instance */;
        return P && P->bIsCrouched;
    }

    virtual FText GetConditionDescription_Implementation() const override
    {
        return NSLOCTEXT("MyGame", "Crouch", "Player is crouching");
    }
};
Override GetConditionDescription

It is the label shown on graph nodes and in the debug HUD. Skip it and a designer reading the graph sees a class name where the rule should be, which makes a Branch much harder to review.

Conditions are evaluated from the first check rather than only on a change, so a condition already true when a Wait For Condition starts succeeds almost immediately. Keep NativeEvaluate cheap: it may run every frame, and the Check Interval that throttles it is a designer-facing field you do not control.
