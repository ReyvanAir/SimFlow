Developer Guide

Writing a Custom Node

Base class
USimFlowNode
Language
C++ only. Tasks and conditions do not have this restriction.
Registration
Automatic. The schema scans subclasses.

Write a node when you need new routing behaviour: a different way for execution to fan out, converge or repeat. If you only need new work, write a task instead, which you can do in Blueprint.

A complete node

UCLASS(DisplayName = "Wait For Actor Tag")
class MYGAME_API USimFlowNode_WaitForActorTag : public USimFlowNode
{
    GENERATED_BODY()
public:
    USimFlowNode_WaitForActorTag() { RebuildPins(); }

    UPROPERTY(EditAnywhere, Category = "Wait")
    FName ActorTag;

    virtual void BuildPins() override
    {
        AddInputPin(SimFlowPins::In);
        AddOutputPin(SimFlowPins::Out);
    }

    virtual void ExecuteInput(FName PinName) override
    {
        ActiveTime = 0.f;   // stay active; TickNode does the work
    }

    virtual void TickNode(float DeltaTime) override
    {
        Super::TickNode(DeltaTime);
        if (/* found */) TriggerOutput(SimFlowPins::Out);
    }

    virtual FText GetNodeCategory() const override
    {
        return NSLOCTEXT("MyGame", "Cat", "My Game");
    }
};

The rules that are easy to get wrong

  1. Call RebuildPins() in the constructor

    The virtual dispatches correctly there, because the derived constructor body is already running.

  2. Override BuildPins, not RebuildPins

    RebuildPins is the non-virtual wrapper that preserves links by name. See rebuilding pins.

  3. Call Super in TickNode

    Otherwise ActiveTime never accumulates, and anything reading elapsed time on your node reads zero.

  4. Decide whether you stay active

    Returning from ExecuteInput without calling TriggerOutput or FinishNode leaves the node active and ticking. That is correct for a waiting node and a bug in an instant one.

    If your node must survive its own output, pass bStayActive = true to TriggerOutput, and override AllowsReentrantActivation() if execution can arrive again while you are still running.

How it reaches the graph menu

Nothing to register. The schema iterates every non-abstract USimFlowNode subclass whose CDO returns true from IsPlaceableInGraph(), groups them by GetNodeCategory(), and labels each with the CDO's GetNodeTitle().

Override IsPlaceableInGraph() to return false for a base class you never want placed directly. Override IsEntryNode() if your node is a new kind of entry point.

Runtime state and saves

Your node is duplicated per run, so plain UPROPERTY members are safe to use as runtime state. They will not survive a save on their own.

To persist, override SaveNodeState and LoadNodeState and use the fields on FSimFlowNodeSaveState: bActive, ActiveTime, ActiveInputPin, IntState, ReceivedInputs, CustomData. Save and load internals covers the ordering guarantees.

Nodes cannot reference level actors

They live in the asset, which knows nothing about any particular level. Resolve actors at runtime by tag through an Actor Query, pass them through the blackboard, or invert the dependency and have the actor raise an event your node listens for.
