Developer Guide

Diagnostics and Known Limits

Log categories
LogSimFlow (runtime), LogSimFlowEditor (editor)
Console
SimFlow.Debug, SimFlow.CreateSample
Validation
USimFlowAsset::ValidateFlow, Blueprint-callable

Logging

Module startup logs at Display, so it appears without changing verbosity. If you do not see the SimFlow startup lines in the Output Log, the module did not load, and nothing further in this guide will help until that is fixed.

SimFlow.Debug 1        on-screen overlay for every running flow
SimFlow.Debug 0        off
SimFlow.CreateSample   build the sample flow asset (editor)

Per-flow, tick bShowDebugHUD on the component. For a world-space VR panel, call GetDebugText() and render the string yourself. USimFlowSubsystem::BuildGlobalDebugText() gives you the same for every running flow at once.

Validation

ValidateFlow(OutErrors, OutWarnings) is public and Blueprint-callable rather than editor-only, so it is reachable from a commandlet or an automation test. It reports:

  • Missing Start nodes
  • Dangling links
  • Task nodes with no task assigned
  • Unreachable nodes
  • Nodes with no outgoing connections
It checks structure, not behaviour

A task with no time limit, waiting on an event nothing raises, is a perfectly valid graph. Validation passes and the flow hangs. Wiring validation into CI catches the structural class of bug and none of the runtime class.

Known limitations

Current as of 1.1.4
LimitationDetail
Join Wait For Any leaves the loser running The node stays alive to swallow the late arrival so downstream cannot fire twice, but the losing branch's task keeps running until the flow ends.
Blackboard replication resends the whole array Fine for tens of keys at tutorial pacing. Move to a FastArraySerializer beyond that.
Presentation multicasts are reliable Appropriate for a flow that changes task every few seconds, not for high-frequency events.
Object values are neither saved nor replicated By design. Resolve actors at runtime.
Custom nodes require C++ Tasks and conditions do not.
Tasks cannot reference level actors They live in the asset. Resolve by tag, pass through the blackboard, or invert to a delegate listener.
A task with no time limit and no other exit hangs silently No error, no log line. ValidateFlow does not catch it, because it is a runtime condition rather than a graph-structure one.
An unconfigured Wait For Event succeeds immediately It logs a warning, but a silent success is arguably the wrong default.

Version history

VersionNotes
1.1.4 Fewer decisions to set up a placement check: a zone shows Settle Mode (Instant, Standard, Custom) in place of five settling and filtering fields, and Place Object In Zone leads with the four a drill actually needs. Standard reproduces the old defaults exactly, nothing was renamed or removed, and a zone saved with tuned numbers loads as Custom. Fixed: a rejected item was graded a near miss whatever it was. .uplugin Version 7.
1.1.3 Items report their own held state (Set Held, Is Held) so a zone no longer infers release from attachment, which was wrong for constraint-based grab systems including VRExpansion's default grip. A payload that is neither an Actor nor an Actor Component now logs a warning instead of failing silently. .uplugin Version 6.
1.1.2 Object recognition: USimFlowIdentityComponent, FSimFlowActorQuery and match grading; ASimFlowZone; the Place Object In Zone and Ordered Sequence tasks; a first-class mistake record. Wait For Event stopped discarding the event payload. .uplugin Version 5.
1.1.0 Optional server-authoritative multiplayer replication: bReplicateFlow, USimFlowPlayerComponent, FSimFlowNetState. .uplugin FileVersion 3 / Version 4, EngineVersion 5.6.0.
1.0.x Single-player: node graph authoring, sequential and parallel tasks, conditions, branching, pause and resume, retry, skip and fail, save and load, sub-flows.
