The graph is a view

Runtime nodes are outered to the asset so they survive cooking, when the UEdGraph is stripped. That single fact drives most of the awkward code in this module.

USimFlowGraphNode::RuntimeNode is marked Instanced so copy and paste duplicates it. Around that:

HookWhat it does
PrepareForCopyingTemporarily re-parents the runtime node onto the graph node so export picks it up.
PostCopyNodePuts it back under the asset.
PostPasteNodeRe-outers to the asset, assigns a fresh Guid, clears the pasted links.
A fresh Guid on paste is not cosmetic

Links, save data and replication all address nodes by Guid. A pasted node that kept its original Guid would collide with the node it was copied from, and the collision would surface as a save restoring the wrong node.

CompileToAsset

It runs on every graph change, on save, and on details-panel edits. It rewrites positions, comments and all pin links from the visual state, clearing the old links first.

So the authored truth is the asset, and the graph can be rebuilt from it at any time with RebuildFromAsset. A corrupted visual layout is recoverable; a corrupted asset is not.

Pin synchronisation

Node property changes call RebuildPins() and broadcast OnPinsChanged. The graph node listens and re-syncs its Slate pins, preserving connections by name. That is the mechanism behind a Branch keeping its wires when you add a case at the end, and losing them when you insert one in the middle.

How the node menu is built

The schema iterates every non-abstract USimFlowNode subclass whose CDO returns true from IsPlaceableInGraph(). Category comes from GetNodeCategory(), label from the CDO's GetNodeTitle(). Nothing needs registering. See writing a custom node.

The validation tab

It calls USimFlowAsset::ValidateFlow(OutErrors, OutWarnings), which is public and Blueprint-callable rather than editor-only. You can run it from a commandlet or an automation test. It reports missing Start nodes, dangling links, task nodes with no task, unreachable nodes, and nodes with no outgoing connections.

ValidateFlow checks structure, not behaviour

It cannot catch a task with no time limit that waits on something that never arrives. That is a runtime condition, not a graph-structure one, and it stays silent. See known limits.
