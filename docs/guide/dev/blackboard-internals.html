Developer Guide

Blackboard and FSimFlowValue

Classes
USimFlowBlackboard, FSimFlowValue
Shape
A tagged union kept as a plain USTRUCT
Types
Bool, Int, Float, String, Name, Vector, Object

Why a plain USTRUCT: it survives SaveGame serialisation and replicates without a custom NetSerialize. That constraint shapes the whole design.

FSimFlowValue

FSimFlowValue::MakeFloat(12.5f);
Value.AsNumber();   // best-effort numeric (bool -> 0/1, string -> Atof)
Value.AsBool();
Value.AsString();
Value.Compare(ESimFlowCompareOp::GreaterOrEqual, Other);
Value.Add(Other);                // numbers, strings, vectors
Value.StripObjectReferences();   // before saving

The full set of constructors is MakeBool, MakeInt, MakeFloat, MakeString, MakeName, MakeVector and MakeObject.

Comparison coerces rather than failing

A String "5" compares equal to an Int 5. That is deliberate, so a designer who picked the wrong type in a dropdown still gets a working condition. It also means a type mismatch never raises an error you could catch, which is why the wrong-type bugs in troubleshooting are all silent.

Add is type-dependent

Add sums numbers, adds vectors component-wise, and concatenates strings. Adding "1" to "1" gives "11". Every counter bug reported against the plugin traces back to this line.

The store

USimFlowBlackboard, the parts that matter to a developer
MemberPurpose
ToEntries(bStrip)Flattens the map to an array for saving and replication. Drops object values when bStrip is set, which it is by default.
FromEntries(Entries, bClearFirst)Restores from that array.
MergeFrom(Other, bOverwriteExisting)Copies every entry from another blackboard. This is what Sub Flow uses in both directions.
OnValueChanged(Key, NewValue)Fires on every write. The component listens to it to mark the replicated blackboard dirty.
AddScore / GetScoreScore helpers over the well-known Score key.

Typed accessors (GetFloat, SetVector and the rest) are all Blueprint-exposed. Keys are FName and match case-insensitively, like every Unreal name.

Well-known keys

Declared in namespace SimFlowKeys. Treat these names as reserved, because the built-in tasks read and write them.

ConstantWritten by
SimFlowKeys::ScoreTask success and failure scoring, AddScore.
SimFlowKeys::MistakesThe Quiz task when Count Mistakes is on.
SimFlowKeys::LastResultThe runtime, after each task finishes.
SimFlowKeys::LastAnswerIndexThe Quiz task.
SimFlowKeys::LastAnswerCorrectThe Quiz task.
SimFlowKeys::WrongAttemptsIncremented every time a task rejects the wrong object.
SimFlowKeys::CurrentStepThe step an Ordered Sequence task is waiting on.

Object references are deliberately not persisted

A raw pointer has no meaning across a save or a network boundary

StripObjectReferences runs before serialisation, and ToEntries drops object values by default. If you need an actor to survive a reload, store something that can be resolved again: an identity tag, a name, or a stable id you can look up.
