Blueprint Nodes

Subsystem Nodes

Class
USimFlowSubsystem, a Game Instance Subsystem
Get a reference
Get Game Instance Subsystem → class SimFlowSubsystem
Target pin
The subsystem
Category
SimFlow, SimFlow | Control, SimFlow | Save, SimFlow | Debug

Use them for: the three things the statics do not cover — the full component list, Stop All Flows, and the debug HUD.

Every SimFlow Component registers itself here on BeginPlay and unregisters on EndPlay. The subsystem is the list.

It outlives level travel, since it belongs to the game instance rather than the world. That makes it the right place to ask "what flows exist" from UI code that has no idea what is in the level.

Most of what it does is also on USimFlowStatics in static form, which needs no reference and is shorter to wire.

Finding flows

USimFlowSubsystem, the registry
NodeReturns
Get All Flow ComponentsEvery registered flow, in registration order.
Find Flow By IdOne flow, or null.
Get Primary FlowThe first running or paused flow, else the first registered, else null.

Get All Flow Components is the one with no static equivalent. Use it to build an instructor panel listing every scenario in the level, or to check how many flows are live before assuming there is one.

Registration order is BeginPlay order, which is not something to depend on. If you care which flow you get, give them Flow Save Id values and look them up by name.

Bulk control

USimFlowSubsystem, every flow at once
NodeNotes
Pause All Flows
Resume All Flows
Stop All FlowsEvery flow reports Aborted.

None of these check authority. On a client with replication on they change the local mirrors and the next server update reverts them.

Stop All Flows has no static wrapper, so this is the only way to reach it from Blueprint.

Save and load

USimFlowSubsystem, slot persistence
NodeReturns
Save All Flows To Slotbool
Load All Flows From SlotHow many flows were restored.
Delete Save Slotbool. Static, so the node has no target pin.

One slot holds every registered flow, matched back by Flow Save Id. A flow with no id can be written but never matched on load. Authority-only, like all SimFlow persistence.

Debug HUD

USimFlowSubsystem, diagnostics
NodeNotes
Set Debug HUD EnabledToggles the overlay for every flow.
Is Debug HUD Enabledbool
Build Global Debug TextCombined status text for every registered flow.

Set Debug HUD Enabled is the Blueprint equivalent of SimFlow.Debug 1. Both drive the same flag, so a console toggle changes what Is Debug HUD Enabled returns.

Build Global Debug Text is the VR answer

The screen-space overlay is not visible in a headset. This node returns the same content as a string, so you can put it on a world-space widget the player can actually look at. For a single flow, Get Debug Text on the component is narrower and usually more readable.

A scenario picker

Listing every flow in the level so an instructor can start one:

  1. Get Game Instance Subsystem → SimFlowSubsystem.
  2. Get All Flow Components.
  3. For each, Get Flow Asset then Get Display Name Text for the button label.
  4. On click, take that component's Get Effective Save Id and pass it to Request Flow Control with Start.

Going through Request Flow Control rather than calling Start Flow directly keeps the panel working on a client.

When it misbehaves

SymptomCause
Get All Flow Components is empty on BeginPlayComponents register during their own BeginPlay, and yours may run first. Check on the first tick.
A destroyed flow looks like it is still listedIt is not. The subsystem holds weak pointers and skips dead entries. What you are seeing is a component whose actor still exists.
The debug HUD will not turn offSimFlow.Debug and Set Debug HUD Enabled share one flag, but the component's own Show Debug HUD checkbox is separate and wins for that flow.
Stop All Flows recorded Aborted, not FailedThat is what it reports. Route through a Finish node for Failed.
The subsystem is nullIt needs a valid world context. This happens in construction scripts and in the editor preview.
