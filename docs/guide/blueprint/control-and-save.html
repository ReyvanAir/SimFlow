Blueprint Nodes

Control and Save Nodes

Library
USimFlowStatics
Target pin
None. These are static.
Authority
Request Flow Control routes itself. The rest do not.
Category
SimFlow | Control, SimFlow | Save

Use them for: instructor panels, pause menus, and anything that has to act on more than one flow at a time.

The SimFlow Component already covers controlling one flow. These nodes cover the two cases it cannot: acting on every flow at once, and sending a control request from a client without holding a component reference.

Request Flow Control

The Request pin offers Start, Stop, Restart, Pause, Resume, Toggle Pause, Retry Current Task, Skip Current Task and Fail Current Task.

It takes the right route on its own. If the PlayerController has a SimFlow Player Component, the request goes through it: a server RPC from a client, a direct call on the server. Without one it looks the flow up with Find Flow By Id and calls the matching component function directly, which is correct in single player and on the server.

That makes it the node to build instructor panels from. The same Blueprint works standalone and as a client, and one node with the enum pin promoted to a variable can drive a whole panel.

A request that reaches the server is checked by Is Request Authorised before anything happens, so a client asking to skip is not automatically obeyed.

Every flow at once

USimFlowStatics, bulk control
NodeEffect
Pause All FlowsPauses every registered flow.
Resume All FlowsResumes every registered flow.

Both forward to the subsystem. Neither checks authority, so on a client they pause the local mirrors and the next server update undoes it. Call them on the server, or in single player.

There is no Stop All Flows static. That one exists only on the subsystem, reachable through Get Game Instance Subsystem.

Save and load, across every flow

USimFlowStatics, persistence
NodeReturnsNotes
Save All FlowsboolWrites every registered flow into one slot.
Load All Flowsint32How many flows were restored.
Delete Flow SaveboolRemoves the slot.

User Index is the platform user index and defaults to 0. Load Mode is Exact State or From Last Checkpoint, the same two modes the component uses.

Load All Flows returning 0 does not mean the slot was missing

Flows are matched into the save by Flow Save Id. A flow whose id changed since the save was written, or never had one, is simply not found. The node returns zero and nothing is logged.

Object references in a blackboard are stripped on save. Save and load are authority-only, like the rest of SimFlow persistence; on a client they log and return.

A pause menu that works in both modes

  1. Give the flow a Flow Save Id, say MainTutorial.
  2. Add a SimFlow Player Component to your PlayerController Blueprint.
  3. Wire each menu button to Request Flow Control with that id.
  4. For the resume button use Toggle Pause rather than tracking state yourself.

Nothing in the menu needs to know whether it is running standalone or as a client.

When it misbehaves

SymptomCause
Nothing happens when a client presses a buttonThe PlayerController has no SimFlow Player Component, and the fallback path found no flow with that id either.
The server ignores a client's skip requestIs Request Authorised rejected it. Check Restrict To Owned Flows, or your override.
Pause All Flows pauses, then un-pausesCalled on a client with replication on. The server's next state update overwrites the mirror.
Load All Flows returns 0 and the slot existsThe flows in the level have different Flow Save Id values from the ones in the save, or none at all.
