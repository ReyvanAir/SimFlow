Blueprint Nodes

Value Nodes

Library
USimFlowStatics
Struct
FSimFlowValue
Target pin
None. All static, all pure.
Category
SimFlow | Value

Use them for: writing a blackboard key from Blueprint, and formatting run state for a tutorial panel.

A SimFlow Value is the tagged union every blackboard key holds. Anywhere a node asks for one you can either break out the struct by hand and set Type plus the matching field, or use a maker. The makers are shorter and cannot produce a mismatched struct.

Making a value

Make SimFlow Value, seven overloads
NodeTakes
Make SimFlow Value (Bool)bool
Make SimFlow Value (Int)int32
Make SimFlow Value (Float)float
Make SimFlow Value (String)FString
Make SimFlow Value (Name)FName
Make SimFlow Value (Vector)FVector
Make SimFlow Value (Object)UObject reference
A hand-built struct with the wrong Type reads as unset

Set Int Value to 5 but leave Type at None and the value is unset as far as every reader is concerned. Nothing warns you, and the condition built on it is quietly always false.

Object values are runtime only. They are cleared when a flow is saved, so store an identifying String alongside anything that has to survive a save.

Reading a value back

Flow Value To, four conversions
NodeReturnsConversion
Flow Value To BoolboolAny non-zero number is true.
Flow Value To Intint32Rounds, so 2.6 becomes 3.
Flow Value To FloatfloatStrings are parsed with Atof.
Flow Value To StringFStringAny type renders to text.

These never fail. They coerce, and an unset value reads as zero or empty. Flow Value To Int rounding rather than truncating is the one that catches people out.

There is no Flow Value To Vector or Flow Value To Object. Break the struct and read Vector Value or Object Value directly, checking Type first.

Most of the time you need none of these. The typed blackboard getters return a plain bool, int or float already, and they take a default for when the key is missing.

Formatting for UI

USimFlowStatics, text helpers
NodeTakesReturns
Result To TextESimFlowResult"Succeeded", "Failed", "Skipped", "Timed Out", "Aborted"
Run State To TextESimFlowRunState"Not Started", "Running", "Paused", "Completed", "Failed", "Aborted"
Format SecondsfloatMM:SS, zero-padded

The first two read the enum's display name, so they pick up localisation and the spaced forms: TimedOut comes back as "Timed Out".

Format Seconds rounds up and clamps at zero, which is what a countdown wants. Two tenths of a second left still reads 00:01, and a negative value reads 00:00 rather than counting backwards. Minutes are not capped, so 90 minutes reads 90:00.

When it misbehaves

SymptomCause
A value written with a hand-built struct reads as unsetType was left at None. Use a maker node.
An Int came back one higher than expectedFlow Value To Int rounds. Use the float form and truncate yourself.
A countdown sits at 00:00 the whole taskThe task has no Time Limit, so remaining time is -1 and the formatter clamps it.
