Blueprint Nodes

Flow Access Nodes

Library
USimFlowStatics
Add via
Right-click in any Blueprint graph → type the node name
Target pin
None. These are static.
Category
SimFlow

Use them for: getting hold of a running flow from a prop, a widget or a controller, without wiring an actor reference through the level.

Before you can do anything to a flow you need the SimFlow Component running it. These three nodes are how you get one.

USimFlowStatics, flow lookup
NodeReturnsUse when
Get Primary FlowThe main running flow, or nullOne scenario is running. The common case.
Find Flow By IdThe flow with that Flow Save Id, or nullSeveral flows are running
Get Flow From ActorThat actor's component, or nullYou already have the actor

All three are pure nodes, so they have no execution pins and re-run wherever you drag the output.

Get Primary Flow

It returns the first flow that is running or paused. When none are, it falls back to the first flow registered with the subsystem, which is usually one that has not started yet.

That fallback is deliberate. It means you can call the node on BeginPlay and get a valid component back to call Start Flow on. It also means a non-null return does not prove anything is running, so check Is Flow Running when that matters.

"First" means first registered, which is BeginPlay order. With one flow in the level that is unambiguous. With several it is not, so use Find Flow By Id instead.

Find Flow By Id

It matches against the component's Flow Save Id. An empty or None id never matches anything, so a flow you want to address this way needs that field set.

The same lookup backs Send Flow Event and the client control routing, which is why setting Flow Save Id is worth doing the moment you have more than one flow.

Get Flow From Actor

A thin wrapper around Find Component By Class. Useful in an overlap or interaction handler where you already have the other actor and want to know whether it hosts a flow.

Raising events

Broadcast Flow Event and Send Flow Event live in this same library. Chapter 05 covers them in full.

On a client, Broadcast Flow Event does not touch local mirrors

It sends a single RPC through the local SimFlow Player Component and lets the server raise the tag on every flow. With no player component on the PlayerController it logs a warning naming the tag and does nothing else.

A wrist panel that finds its own flow

For a VR status panel that should not need configuring per level:

  1. In the widget's Event Construct, call Get Primary Flow.
  2. Branch on Is Valid.
  3. Store the result and bind your text blocks to Get Current Task Name and Get Current Instruction on it.

Or skip all of that and reparent the widget to SimFlow Status Widget, which does the same thing every frame until it finds a flow.

When it misbehaves

SymptomCause
Get Primary Flow returns null on BeginPlayThe flow's actor has not begun play yet, so it has not registered. Move the call to the first tick.
Find Flow By Id always returns nullThe component's Flow Save Id is still None, which is the default.
The wrong flow comes backTwo flows are running and you got whichever registered first. Give them save ids.
Works in the editor, null in a packaged clientThe flow lives on a server-only actor. Clients only see a flow whose owning actor replicates and whose component has Replicate Flow on.
