Blueprint Nodes

Scenario Selector Nodes

Classes
USimFlowSelectorWidget, USimFlowStatics
Target pin
None on the three statics. The widget nodes target the widget.
Authority
Building and reading a list works anywhere. Starting a scenario is server-side.
Category
SimFlow | Selector

Use them for: the briefing-table panel a trainee picks a scenario from, showing each one's best score and how it went last time.

Status Widget covers the panel shown during a run. This is the panel shown before it: a list of what can be played, and a button that starts one.

Three nodes do the work

The list is built by three statics on SimFlow Statics. They are the whole feature; the widget class below is a convenience wrapper around them.

Scenario selector nodes
NodeTakesDoes
Build Scenario OptionsAn array of flow assetsReturns one option per Start node, carrying display name, description and record key. Leaves the history empty.
Apply Scenario RecordsThe options, a slot nameFills in best score, play count, last outcome and last played, reading the slot once for the whole list.
Start ScenarioA flow component, one optionEnds whatever was running, points the flow at the pick, starts it.

One asset per scenario, or many entries in one

Both authoring shapes work, and there is no setting to choose between them. Build Scenario Options expands every Start node it finds:

  • An asset with a single Default entry becomes one option, labelled with the asset's Flow Display Name.
  • An asset holding three Start nodes becomes three options, each labelled with its entry name.

An asset with no Start node is skipped with a warning, because a button for it could never start anything.

What an option carries

FSimFlowScenarioOption
FieldHolds
Flow AssetThe asset this option starts.
Entry NameWhich Start node to begin from.
Display NameButton label. The asset's display name, or the entry name when one asset holds several.
DescriptionThe asset's Flow Description.
Save IdThe record key. The asset's name, or Asset.Entry for a multi-entry asset.
RecordBest score, play count, last outcome, last played. All zero until Apply Scenario Records runs.
Has RecordTells a stored 0 from never played. Check this before showing a number.

Without the base class

Nothing here needs SimFlow Selector Widget. The three nodes are static, so a widget on any parent class — including one belonging to another plugin — builds its own list:

Event Construct
  └─▶ Build Scenario Options ( your flow assets )   ──▶  [ Options ]
        └─▶ Apply Scenario Records ( Options, Slot = "" )
              └─▶ For Each ──▶ one button per option
                               label        = Display Name
                               subtitle     = Description
                               best / plays = Record.Best Score, Record.Play Count

On button clicked
  └─▶ Get Primary Flow  ──▶  Start Scenario ( Flow, Option )

Leave Slot Name empty and it resolves to SimFlowScenarios. Keep the options in a variable rather than rebuilding them every frame: each Apply Scenario Records opens the save file.

With the base class

Reparent your briefing-table widget Blueprint to SimFlow Selector Widget and it holds the list and the target flow for you.

Each pick gets its own history

Scenario records are keyed by the component's Flow Save Id. One briefing table running six scenarios through one component would file all six plays under that component's single id, and their histories would merge into one meaningless total.

So Start Scenario writes the option's Save Id to the component first. Assign Save Id is on by default; turn it off only if your project keys records another way.

Renaming a flow asset starts a fresh history

The key is derived from the asset's name, so TrafficDrill renamed to TrafficScenario reads as a scenario nobody has played. Rename before you ship, or key the records yourself.

Authority

Building a list and reading history work on any machine. Starting does not: with Replicate Flow on, a client cannot hand the server a different asset, so Start Scenario logs a warning and forwards a plain start request, and the server runs whatever it has configured. Pick the scenario server-side, or give each trainee an unreplicated flow.

Records are also written server-side, so a client reading its own local slot finds nothing unless your project sends the numbers across. See Scenario Records.

When it misbehaves

Symptoms
SymptomCause
A scenario is missing from the listIts asset has no Start node. Check the log for the warning naming it.
Every option shows a best score of 0Apply Scenario Records was never called, or the slot name does not match the component's Scenario Slot Name.
A never-played scenario shows “Best: 0”Read Has Record first — a stored 0 and never played both read as 0.
Every scenario shares one play countAssign Save Id is off, so all picks file under the component's id.
Select Scenario returns false and nothing startsNo flow to run it on. Place a SimFlow Component, or set Flow Save Id to name one.
The panel never updates after a runOptions cache their history. Call Refresh Records on On Flow Finished.
