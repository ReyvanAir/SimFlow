Task Reference

Delay Task

Class
USimFlowTask_Delay
Select via
Task node → Task dropdown → Delay
Finishes with
Succeeded, once the wait elapses
Category
Timing

Use it for: a wait that needs something the Delay node cannot give you: a random extra, a place inside a Parallel Group, or a Task node's abort condition around it.

For a plain pause in the graph, the node form is the better choice.

How long it waits

USimFlowTask_Delay, own settings
FieldTypeDefaultMeaning
DurationFloat, seconds, min 01.0Base wait time.
Random ExtraFloat, seconds, min 00.0Randomly adds up to this many seconds on top of Duration.

Plus the fields every task has.

The actual wait is Duration + random(0, Random Extra), rolled once when the task starts. With both at 0 the task finishes almost immediately, effectively a pass-through. With Duration at 0 and Random Extra set, you get a purely random wait between zero and that value.

Tick While Paused is almost never what you want

Pausing the flow normally stops the timer and resumes it where it left off. Turn on the base Tick While Paused field and the delay keeps counting through the pause instead.

Node or task?

Use the Delay node

  • A plain pause, which is the usual case
  • You want the graph to read clearly

Use the Delay task

  • You want Random Extra
  • You want it inside a Parallel Group
  • You want a Task Id, an instruction, or scoring attached
  • You want the Task node's abort condition around it

Varied ambient pacing

An idle scenario where a radio call arrives every twenty to thirty seconds, so it does not feel scripted.

  1. Add the task

    A Task node with Task set to Delay.

  2. Set the window

    Duration to 20, Random Extra to 10, making the wait 20 to 30 seconds.

  3. Wire the payoff

    Completed into the radio-call task.

  4. Repeat it

    Wrap the pair in a Loop node with Iterations of 0 and a break condition, so the calls repeat until the scenario ends.

    Let a real event cut the wait short. On the Task node, set Abort Condition to Event Was Raised with your interrupt tag and Abort Result to Succeeded.

When it misbehaves

SymptomCause
The delay runs longer than configuredRandom Extra is set. It adds on top of Duration rather than blending into it. Or the flow was paused.
The delay does not pause with the gameTick While Paused is on, or the component's Follow Game Pause is off.
You wanted a timeout, not a pauseUse the Task node's Time Limit, or race a delay against the work with a Join in Wait For Any mode.
The graph is filling with Task nodes that only waitThe Delay node exists for exactly that.
