Task Reference

Wait For Event Task

Class
USimFlowTask_WaitForEvent
Select via
Task node → Task dropdown → Wait For Event
Finishes with
Succeeded on an accepted payload, or Failed under the strictest policy
Category
Waiting

Use it for: the main way the world advances a flow. A button, a grabbable object or an animation notify raises a tag, and this task is waiting for it.

Expected Payload is what makes it more than a doorbell. Ten buttons can broadcast the same tag while knowing nothing about the procedure, and only the intended one satisfies the task.

Accept Already RaisedBoolfalseIf the tag was raised earlier in this run, finish straight away.

FieldTypeDefaultMeaning
Expected PayloadActor QueryemptyWhich object the event has to be about.
Mismatch PolicyEnumCount Mistake (Keep Waiting)What happens when the tag is right but the object is not.
Payload To Blackboard KeyNameNoneStores the accepted payload, so later tasks can refer to "the thing they picked".

Plus the fields every task has.

An empty Event Tag logs "WaitForEvent task has no tag set - finishing immediately" and finishes with Succeeded, a no-op pass-through rather than a failure. An empty Expected Payload means the payload is not checked at all, so any sender satisfies the task. That is a legitimate "do not care" and often exactly what you want.

If the tag is never raised, the task waits forever. Set a Time Limit on the Task node while developing.

Why a payload check disables Accept Already Raised

Set both and the already-raised shortcut is ignored, with a Verbose note in the log.

The reason is that a past event kept only its tag. The payload was not retained. Honouring "already raised" when there is a payload check would let the wrong object satisfy the task silently, so the task waits for a fresh event instead.

What counts as a payload

A UMG widget can never satisfy a payload check

An Actor Component is unwrapped to its owning actor and graded normally, so a button Blueprint sending the pressed component works fine. UUserWidget is neither an Actor nor an Actor Component, so it scores No Match and logs a warning. Broadcast from the owning actor with Payload = self instead. This is the most common first bug in the plugin.

How a matching event is handled

  1. Compare the tag

    Matches Tag when Match Child Tags is on, exact equality otherwise. A non-match is ignored silently.

  2. Grade the payload

    If Expected Payload is set, the payload is graded by the Actor Query. An Exact match carries on.

  3. Anything else is a mismatch

    Fires On Payload Rejected, builds a mistake description like "Interacted with Wrench - expected Item.Extinguisher.Foam", applies the Mismatch Policy, and does not complete the task.

  4. On acceptance, store and finish

    The payload is stored to Payload To Blackboard Key if you set one, and the task finishes with Succeeded.

    On Payload Rejected gives you the payload and the match quality, which is enough to sound a buzzer, outline the object red, or give a different hint for a near miss than for something completely unrelated.

Mismatch Policy
ValueBehaviour
Ignore (Keep Waiting)Stays silent.
Count Mistake (Keep Waiting)Records a SimFlow.Mistake.WrongTarget mistake and carries on waiting. The default.
Count Mistake And Fail TaskRecords it and drives the Failed pin.

The right valve, among five

The trainee must turn valve 3. All five valves broadcast the same tag.

  1. Give the valves an identity

    Add a SimFlow Identity to the valve Blueprint, and on the level instances set Identity Tags to Control.Valve.One through Control.Valve.Five.

  2. Make them report neutrally

    In the valve Blueprint, when it is turned, call Broadcast Flow Event with Event Tag SimFlow.Event.Interact and Payload self.

  3. Set up the task

    A Task node with Task of Wait For Event. Event Tag of SimFlow.Event.Interact, Expected Payload → Required Tags of Control.Valve.Three.

  4. Choose the wrong-object behaviour

    Mismatch Policy of Count Mistake (Keep Waiting), so the trainee can self-correct. Set Payload To Blackboard Key to LastValve if a later task needs to refer back to it.

  5. Tell them, and give feedback

    Instruction of Turn valve 3. Bind On Payload Rejected to flash the correct valve after a wrong attempt.

    None of the five valves knows anything about the exercise. Moving the answer to valve 4 is a one-field change in the flow asset.

When it misbehaves

SymptomCause
The task completed instantly and nothing happenedEvent Tag is empty, which finishes immediately by design.
The task never fires though the event is broadcastThe tags do not match. Check Match Child Tags, and confirm the broadcast actually runs with a print node.
A warning says the payload is "neither an Actor nor an ActorComponent"You broadcast self from a UMG widget graph. Broadcast from the owning actor instead.
Any object satisfies the taskExpected Payload is empty.
Accept Already Raised does nothingYou also set an Expected Payload, which disables it.
The flow hangs here foreverNothing raises the tag. Add a Time Limit on the Task node and wire Timed Out to a hint.
