Task Reference

Set Blackboard Value Task

Class
USimFlowTask_SetBlackboard
Select via
Task node → Task dropdown → Set Blackboard Value
Finishes with
Succeeded, immediately
Category
Data

Use it for: a blackboard write that needs to sit inside a Parallel Group, or that wants a Task Id or scoring attached.

The node form has identical fields and is the better choice for a simple write in the graph.

Fields

USimFlowTask_SetBlackboard, own settings
FieldTypeDefaultMeaning
KeyNameNoneWhich blackboard key to write.
ValueSimFlow ValueType NoneSet the Type first and the matching value field appears.
AddBoolfalseAdd to the existing value instead of replacing it.

Plus the fields every task has.

Both empty-field cases are silent

Leaving Key as None writes under the literal key name None, with no warning. Leaving Value Type as None stores an unset value that conditions cannot usefully compare against. A key-name typo has the same character: it yields a condition that is quietly always false.

Adding to a missing key creates it with the delta as the value. Adding across mismatched types coerces rather than failing. Adding on a String concatenates, so "1" plus "1" is "11". Use Int for counters.

Scoring a step inside a parallel group

While the trainee performs a check, record that the briefing was delivered as part of the same group, so it cannot be skipped separately.

  1. Add the group

    A Task node with Task set to Parallel Group.

  2. Child 0 is the real work

    The check task itself.

  3. Child 1 is the record

    Set Blackboard Value: key BriefingDelivered, value type Bool, value true, Add off.

  4. Require both

    Leave the group's Wait For All on. A later Branch can then test BriefingDelivered with Blackboard Compare.

    For a plain write between two steps, the node form reads better and costs less.

When it misbehaves

SymptomCause
A later condition never sees the valueThe key names differ. They are case-insensitive, but spelling is not forgiven. Print the blackboard with SimFlow.Debug 1.
A counter became "111"Type is String with Add on. Switch to Int.
The value vanished after loading a saveThe type is Object, and object references are stripped on save.
