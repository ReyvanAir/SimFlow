Task Reference

Parallel Group Task

Class
USimFlowTask_ParallelGroup
Select via
Task node → Task dropdown → Parallel Group
Finishes with
Succeeded when the wait condition is met; Failed if a child fails and the option is on
Category
Composition

Use it for: a small parallel group without cluttering the graph with Parallel and Join nodes. "Play the narration while the trainee dons the helmet" becomes one node rather than five.

Fields

USimFlowTask_ParallelGroup, own settings
FieldTypeDefaultMeaning
TasksArray of instanced tasksemptyThe child tasks. Each gets its own class dropdown and inline settings.
Wait For AllBooltrueWith this off, the group finishes as soon as the first child does.
Fail If Any Child FailsBooltrueAny child failing fails the whole group.

Plus the fields every task has.

An empty Tasks array never advances

There is nothing to wait for and no child to report completion. Treat that as a configuration error rather than a way to no-op a node.

With Wait For All on, a child that never finishes holds the group forever. Put a Time Limit on the Task node. With it off, the first child to finish ends the group and the others with it, so do not rely on their side effects having completed.

What the children inherit

Child tasks are full tasks, so each carries its own presentation, rules and scoring fields. Three consequences follow.

  1. Each child's scoring applies

    Three children with Score On Success of 10 add 30, on top of whatever the group itself scores.

  2. Pause and resume propagate

    To every child.

  3. There is no per-child timeout

    The group's Time Limit lives on the Task node, not on the children.

    This is the main limitation. If you need per-branch timeouts, use real Parallel and Join nodes so each branch gets its own Task node.

Group, or Parallel and Join?

Choosing between the two shapes
Use Parallel GroupUse Parallel + Join nodes
Two or three simple concurrent tasksBranches with several steps each
You want the graph compactYou want to see the structure in the graph
The branches share one outcomeEach branch needs its own timeout, retry or routing
No per-child failure routing neededYou need a Failed pin per branch

Narration alongside a physical step

A narration line plays while the trainee puts on the helmet. Moving on when the helmet is on, because the narration should not hold things up.

  1. Add the group

    A Task node with Task of Parallel Group. Under Tasks, click + twice.

  2. Child 0 is the real step

    Wait For Event, event tag SimFlow.Event.Grab, with Expected Payload → Required Tags of Item.Helmet.

  3. Child 1 is the narration window

    Delay with a Duration of 8, the length of the narration, with your audio triggered from the Instruction UI.

  4. Let the helmet win

    Turn Wait For All off, so donning the helmet early moves things along. Turn Fail If Any Child Fails off, since the delay cannot fail.

  5. Name it for the UI

    Display Name of Don the helmet.

    If the trainee must both don the helmet and hear the whole briefing, leave Wait For All on.

When it misbehaves

SymptomCause
The group never finishesWait For All is on and a child is waiting for something that never arrives.
A child's work got cut shortWait For All is off, so the first child to finish ended the group and took the others with it.
The score is higher than expectedEvery child's Score On Success contributes, on top of the group's own.
One child needs its own timeoutNot possible inside a group. Use Parallel and Join nodes.
A child failure failed everythingFail If Any Child Fails is on by default. Turn it off for optional children.
