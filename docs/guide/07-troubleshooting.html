Chapter 07

Troubleshooting and Common Pitfalls

SimFlow fails quietly by design. An unwired pin is legal, an empty query matches nothing, and a half-built flow still runs end to end. That makes blocking out a scenario pleasant and makes debugging a finished one a specific skill. This chapter is that skill.

Start with these two tools

The debug overlay, from the console:

SimFlow.Debug 1

draws live flow state on screen: the active node, the current task, elapsed time and the whole blackboard. SimFlow.Debug 0 turns it off.

Reach for it before anything else. Most reports of "it does not work" are answered by seeing which node is actually active and what the blackboard holds. For a single flow rather than all of them, tick Show Debug HUD on the component, or call Get Debug Text to put the same information into a world-space VR widget.

Then the log. SimFlow logs under the LogSimFlow category, so open the Output Log and filter for it. A good number of misconfigurations log a warning naming the exact problem: a task with no zone, an event task with no tag, a loop hitting its iteration cap. Check the log before guessing, because the silent failures below are the ones that log nothing at all, and that is exactly what makes them hard.

The three-question triage

  1. Which node is active right now? (SimFlow.Debug 1)
  2. Did anything log? (filter LogSimFlow)
  3. Does the flow even reach that node? (swap the suspect task for a Log Message)

Those three answers separate "never arrived" from "arrived and stalled", which are completely different bugs and are otherwise indistinguishable.

The seven that account for most of it

01

An unwired output pin ends execution, silently

Symptom
A whole section of the flow never runs. No error, no warning, run state still Running.
Cause
A pin somewhere upstream leads nowhere. This is legal: a flow may have branches that stop, which is precisely why it is not reported.
Fix
Trace back from the first node that never activates. Check Failed and Timed Out on Task nodes, every case pin on a Branch, and the Start node's Out.

The related case: a flow that never ends. Execution running out of wiring does not complete a flow. There must be a Finish node on the path that ran.

02

Missing completion tags and empty fields read as success

Several tasks pass through by design when a required field is empty, so that a half-built flow still runs. The cost is that a genuinely forgotten field looks like a completed step.

ThingEmpty fieldResult
Task nodeTaskWarns, triggers Completed
Wait For EventEvent TagWarns, succeeds
Ordered SequenceStepsWarns, succeeds
Sub FlowSub FlowWarns, triggers Completed

All four log a warning, so this one is findable: filter LogSimFlow. The asymmetry in Ordered Sequence is deliberate. An empty Steps array succeeds because it is a flow nobody has filled in yet; an empty Event Tag fails because it is a task that could never have worked.

03

An empty Actor Query or condition never matches, and never says so

Symptom
A task starts normally and then waits forever. Nothing in the log.
Cause
An empty query returns No Match against everything. It does not fall through to "match anything". An unset condition is false forever.
WhereAn empty value means
Place Object In Zone → Accepted ItemsNothing can ever be accepted. Hangs.
Place Object In Zone → ZoneFails immediately with a warning. This one is loud.
Ordered Sequence → step TargetThat step can never be satisfied. Hangs.
Wait For Condition → ConditionFalse forever. Hangs.
Branch case → ConditionFalse, so that case never fires. Falls to Default.
Wait For Event → Expected PayloadThe payload is not checked at all, so any sender satisfies the task.

Diagnostic that works every time: if the task fails at once, check the Zone. If it never completes, check Accepted Items. That single split resolves most Place Object In Zone reports.

04

Events never reach the flow, usually because of the payload

The most common first bug in the plugin: broadcasting self from inside a UMG widget graph. A UUserWidget is neither an Actor nor an Actor Component, so it can never satisfy a payload check. It logs a warning naming the offending class. Broadcast from the owning actor with Payload = self instead.

After that, work down this list:

  • Does the tag actually match, given Match Child Tags? A mismatch is silent.
  • Is the broadcast running at all? A print node next to it answers that in ten seconds.
  • Are you on a client? Events have to reach the authority, and the component's Send Event is the call that forwards.
  • Did you target the right flow? Broadcast Flow Event hits every running flow; Send Flow Event targets one by Flow Save Id.
05

Loops that run once, and joins that wait forever

SymptomCause
The loop body runs once, then stopsThe Continue pin is not wired back. The classic Loop mistake.
Log says "hit MaxIterations"Iterations is 0 and the break condition never passes.
The body never runsThe break condition is already true on entry. It is checked before each iteration.
The loop stalls partwaySomething in the body ended without returning to Continue, often an unwired Failed pin.
The flow stalls at a JoinNum Inputs is higher than the number of branches that actually arrive. In Wait For All mode the join waits forever, in silence.

Match Num Inputs to the branches you wired. This is the one stall that gives you no log line and no visible state change, so check it early rather than late.

06

Circular prerequisites, and Sub Flow recursion

Two severities of the same shape.

A circular gate is a stall. Gate step A on "B has happened" while B is gated on "A has happened" and both Wait For Condition tasks go on waiting. Nothing errors, because waiting is what they are for. Set a Time Limit on gate tasks during development and wire Timed Out to a Log Message; the stall then names itself.

A Sub Flow cycle hangs the editor

A Sub Flow node that references its own asset, directly or through a chain of assets that loops back, has no recursion guard. Pressing Play hangs the editor rather than logging an error. If the editor locks up the instant you hit Play after adding a Sub Flow, that is the first thing to check, and it is the reason to keep a mental map of which assets include which.

07

Multiplayer replication

SymptomCause
Clients see nothingReplicate Flow is on but the owning actor does not replicate. Host on Game State or Player State.
Client controls do nothingThe PlayerController has no SimFlow Player Component, so there is no route to the server.
Save does nothingSave and load are authority-only. On a client they log and return.
Client UI has no blackboard valuesReplicate Blackboard is off.
A client countdown jumps in one-second stepsElapsed time refreshes on Net Refresh Interval, default 1.0. Interpolate locally rather than lowering the interval.

Structural changes replicate immediately; only the elapsed-time field is throttled. If a client is a whole task behind rather than a second behind, the problem is not the refresh interval.

By symptom

Nothing happens at all

Work down this list. Is Flow Asset set on the component? Is Start Mode still Manual, with nothing calling Start Flow? Does the component's Entry Name match a Start node's Entry Name? Both default to Default, so a rename on one side breaks it silently. Is there a Start node at all, and is its Out pin actually wired?

The flow starts, then cannot find things

Start Mode is Auto - On Begin Play. Other actors may not have begun play yet, so a task that immediately looks for a zone or an item finds nothing. Switch to Auto - On First Tick.

The flow ends too early

Either a Finish node was reached with Stop Other Branches on, which is the default, while another branch was still working (converge branches with a Join first), or a Sub Flow or Task node's Failed pin is unwired and ended that line of execution.

A task never completes

The largest category by far
SymptomLikely cause
Nothing in the logAn empty Actor Query or an empty condition. Both are silently false.
Wait For Condition hangsIts Condition slot is empty, and an unset condition is false forever.
Place Object In Zone hangsAccepted Items is empty, so nothing can ever match.
Ordered Sequence hangs on a stepThat step's Target is empty or does not match.
Quiz hangsNothing calls Submit Quiz Answer.
Wait For Event hangsThe tag never arrives. See gotcha 04.

While developing, set a Time Limit on the Task node and wire Timed Out to a Log Message task. A hang then becomes a message naming the task.

Placement and zones

SymptomCause
Objects count as placed while still heldHeld state is not wired. Call Set Held(true/false) from your grab logic, because attachment alone is unreliable in VR.
Nothing is ever trackedNo collision overlap, or the box is too small. Turn on the zone's Draw Debug; silver means nothing tracked.
The player pawn is trackedRequire Identity Component was turned off.
Objects settle then un-settle repeatedlyJitter above Settle Speed Threshold. Raise Settle Time or the threshold.
The wrong zone is usedTwo zones share a tag, and tag queries take the first world match. Give them distinct tags.

Matching and identity

SymptomCause
The right object is not recognisedIt has no Identity component, or no tags on it.
Everything is No Match, never a near missThe tag tree is flat. Confusable things must share a parent.
Require All Tags blocks everythingWith several tags requested the actor needs all of them. Set it to false for "any".
Tags on a placed instance do not apply to spawned copiesThe component went on the level instance, not the Blueprint.
Setting Identity Id did not helpNothing in SimFlow reads Identity Id. Use Identity Tags.

Conditions and branching

SymptomCause
A branch case never firesIts condition slot is empty, and an unset condition is false.
Everything goes to DefaultThe conditions read a key that does not exist. Missing keys return Result When Key Missing, default false.
An All Of always passesIt has no children. An empty AND is true.
The wrong case firesCases evaluate top to bottom and the first match wins. Put the most specific first.
Execution stops at a branchNothing matched and Has Default Pin is off.

Blackboard

SymptomCause
A value is never seenKey name mismatch. Typos are silent. Print the blackboard with SimFlow.Debug 1.
A counter became "111"The value type is String with Add on, so it concatenated. Use Int.
An object reference is null after loadingObject values are stripped on save, by design.
Get Score always returns 0Score On Success and Score On Failure default to 0 on every task. Scoring is opt-in.

Editing and assets

SymptomCause
Editing the flow mid-play changes nothingNodes are duplicated into the instance at start. Stop and restart the flow.
Wires moved after adding a Branch casePins are named by index, so inserting in the middle renumbers later ones. Add at the end.
The editor hangs on PlayA Sub Flow calls itself, directly or in a cycle. See gotcha 06.
No SimFlow entry in the Content BrowserThe plugin is not loaded, or the editor module failed to build. See Chapter 01.

Still stuck

Run SimFlow.Debug 1 and ask which node is actually active. Filter the Output Log by LogSimFlow. Replace the suspect task with a Log Message and see whether the flow reaches that node at all. Then check the field the task needs is not empty, because most silent hangs are an empty Actor Query or an empty condition, and neither logs anything.

If the behaviour looks like a plugin bug rather than a configuration problem, the issue tracker is at github.com/ReyvanAir/SimFlow/issues. A report is far more useful with the LogSimFlow output and a screenshot of the debug overlay at the moment it stalls.
