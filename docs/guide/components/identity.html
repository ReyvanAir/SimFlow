Components

SimFlow Identity

Class
USimFlowIdentityComponent
Add via
Add Component → SimFlow Identity
Goes on
The item Blueprint, not each placed instance
Category
Identity, SimFlow | Identity

Use it for: telling a flow what an object is, so a task can ask for "any foam extinguisher" instead of pointing at one particular actor in one particular level.

Without identity, every task has to name an actor. That works until the object is spawned at runtime, until there are six of them, or until someone copies the level and renames everything. With identity, the task asks for a tag and whatever carries that tag answers.

The component holds three fields and one runtime flag. That is the whole thing.

USimFlowIdentityComponent, Details panel
FieldTypeDefaultMeaning
Identity TagsGameplay Tag ContaineremptyWhat this object is, for example Item.Extinguisher.Foam. Several tags are fine.
Display NameTextemptyShown in mistake text and tutorial prompts. Falls back to the actor's name.
Identity IdNameNoneOptional stable id for analytics, or for addressing this actor from script.

Put it on the Blueprint, once

Add it to the item Blueprint and every copy you place or spawn carries the same tags. Adding it per level instance gives you the same result on Monday and a scenario nobody can maintain by Friday.

The exception is an object whose meaning genuinely differs between placements: the same panel Blueprint used as "the main breaker" in one room and "the spare" in another. Override the tag on the instance there, and only there.

Naming tags so near misses work

Tags nest, and the nesting is what lets a task tell a wrong-but-reasonable answer apart from a completely wrong one. Ask for Item.Extinguisher and any extinguisher passes. Ask for Item.Extinguisher.Foam and only foam passes, while the CO2 one comes back as a near miss rather than as garbage.

So the naming matters more than it looks. Item.Extinguisher.Foam and Item.Extinguisher.CO2 grade as related; FoamExtinguisher and CO2Extinguisher grade as unrelated, and your feedback loses the distinction it needed to be useful.

Two tags on one object is normal. A foam extinguisher that is also the heavy one can carry Item.Extinguisher.Foam and Property.Heavy, and a query can ask for either.

Set Held, and why it exists

Call Set Held where your grab succeeds, and clear it on release.

A zone cannot work this out on its own. Attachment is only one of the ways a VR framework can hold something: VRExpansion holds most grip types with a physics constraint and never reparents the actor, so an object sitting in the player's hand looks perfectly detached from outside. The zone falls back to checking attachment when nothing sets the flag, which is how an object gets counted as placed while the trainee is still holding it.

With the flag set, Place Object In Zone stops treating a held object as at rest, and placement checks become exact regardless of which VR plugin you use.

Held is not replicated

The flag is transient and local. Zones run on the server, so in multiplayer the grab has to set it there: call Set Held from a server RPC or from replicated grab logic, not from the client-side visual that happens to look right on the trainee's machine.

Display Name is what the trainee reads

Leave it empty and prompts and mistake text fall back to the actor's name, which is how a headset ends up showing "BP_Ext_Foam_2". Filling it in costs one field and survives someone renaming the Blueprint.

Get Identity Display Name reads it from your own Blueprint, for hint text and highlight labels.

Actors you cannot add it to

Two fallbacks, both on the query rather than on the object.

Identifying an actor with no identity component
SituationWhat answers
Actor from a GAS projectIdentity tag reads fall back to IGameplayTagAssetInterface, so its existing tags work with no second component.
Actor from a plugin you do not ownUse Required Actor Tag on the Actor Query, matching a plain AActor::Tags entry.

Gameplay tags are the default for the reasons the fallbacks lack: they are validated at author time, they autocomplete in the Details panel, and they nest, which is what the near-miss grading depends on.

When to skip it

An object no task ever asks about does not need one. Scenery, decoration and anything the trainee cannot pick up can stay plain. Identity is for the objects a procedure has an opinion about.

It is also not a place for state. The component describes what a thing is, not what it is doing; task progress, counters and scores belong on the blackboard.
