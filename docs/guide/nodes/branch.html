Node Reference

Branch Node

Class
USimFlowNode_Branch
Add via
Right-click → Flow Control → Branch
Pins
In → Case 0 … Case N, Default
Category
Flow Control

Use it for: condition-based routing. Pass and fail, difficulty selection, remediation, "have they already done this?" All of it lands here.

Branch evaluates each case in order and leaves through the first one that passes, or through Default when none do. It is the main decision point in most flows.

Fields

USimFlowNode_Branch, Details panel
FieldTypeDefaultMeaning
CasesArrayemptyThe ordered list of conditions. Each one adds an output pin.
Fire All Matching CasesBoolfalseFire every case that passes instead of only the first, fanning out in parallel.
Has Default PinBooltrueShow a Default pin, taken when nothing matched.

Each case holds a Label (a string; empty gives you Case N on the pin) and a Condition, an instanced condition object. An empty condition slot counts as false, so that case never fires.

Add new cases at the end

Internally the pins are named Case_0, Case_1 and so on, rebuilt whenever you add or remove a case. Links survive only as long as the pin name still exists, so inserting a case in the middle renumbers everything after it and moves your wires.

Order matters

Cases are tested top to bottom and the first pass wins, unless Fire All Matching Cases is on. Put the most specific case first:

Case 0:  Score >= 90     "Distinction"
Case 1:  Score >= 70     "Pass"
Default:                 "Fail"

Reverse those two and everything scoring 90 or above leaves through Pass, because it gets tested first and passes.

The silent stop

Nothing matched, and no Default pin

The node finishes without triggering anything, and that line of execution stops dead. Ending a branch this way is legitimate, and that is what makes it hard to spot: it looks identical to a mistake. Check for it when a flow stalls somewhere near a Branch.

A case pin left unwired behaves the same way. It fires, and goes nowhere.

Three-way routing on score

Routing to distinction, pass or remediation at the end of an assessment.

  1. Add the node

    Right-click, then Flow Control → Branch.

  2. Add two cases

    Under Cases, click + twice.

  3. Configure them most specific first

    Case 0: label Distinction, condition Score Threshold, >=, 90. Case 1: label Pass, condition Score Threshold, >=, 70.

  4. Wire the three routes

    Leave Has Default Pin on. Default is the remediation route.

    To require a score and a mistake limit together, set that case's condition to All Of with two children. An empty All Of is true, so make sure it actually has them.

When it misbehaves

SymptomCause
A case never firesIts condition slot is empty, or an earlier and broader case is catching everything before it gets there.
Everything falls through to DefaultThe conditions are reading a blackboard key that does not exist. A missing key makes Blackboard Compare return Result When Key Missing, which defaults to false. Confirm with SimFlow.Debug 1.
Wires moved after adding a casePins are named by index, so inserting in the middle renumbers the ones after it.
Two branches ran at onceFire All Matching Cases is on. Converge them with a Join.
Execution stops at the branchNothing matched and Has Default Pin is off.
