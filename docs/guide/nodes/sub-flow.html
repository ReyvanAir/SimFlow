Node Reference

Sub Flow Node

Class
USimFlowNode_SubFlow
Add via
Right-click → Composition → Sub Flow
Pins
In → Completed, Failed
Category
Composition

Use it for: running another flow asset as a child. This is what makes flows modular.

Extract "don the PPE" or "perform the safety check" into its own asset once, then call it from every scenario that needs it. Fix it in one place and every caller gets the fix.

Fields

USimFlowNode_SubFlow, Details panel
FieldTypeDefaultMeaning
Sub FlowSimFlow AssetnullThe child flow to run.
Entry NameNameDefaultWhich Start node of the child to begin from.
Inherit BlackboardBooltrueCopy the parent blackboard into the child at start.
Write Back BlackboardBooltrueCopy the child's blackboard back into the parent when it ends.

Completed is taken when the child finishes successfully, Failed when it fails or aborts.

How state moves between parent and child

The two blackboard settings give you four arrangements.

Inherit and write-back combinations
InheritWrite BackBehaviour
ononThe default. The child sees everything and its changes come back, which is closest to inlining the section.
onoffThe child reads parent state but its changes are discarded. A sandbox.
offonThe child starts clean and hands results back. Good for a self-contained scored section.
offoffFully isolated.

Both directions are a merge that overwrites by default, not a replace, so keys the child never touched keep their parent values on write-back. Object references move across fine, because this is an in-memory merge rather than a save.

An empty Sub Flow node is a silent pass-through

Four ways this node goes quiet
  • Leave Sub Flow null and the node logs "has no asset assigned" and triggers Completed. It passes through rather than failing.
  • An Entry Name that matches no Start node in the child means the child cannot start.
  • A child with no Finish node never reports completion, so the parent waits on this node forever.
  • A flow that calls itself recurses infinitely. There is no depth guard, and the editor hangs on Play.

Pause, skip and fail

The node forwards all three to the child. Pausing the parent pauses the child. Skip is always allowed here and ends the child. Fail ends the child and leaves through Failed.

A reusable PPE check

Every scenario starts by making the trainee put on a helmet and gloves.

  1. Build the child asset

    Create F_PPECheck with its own Start, two Task nodes and a Finish.

  2. Have it report a result

    A Set Blackboard Value node setting PPEComplete = true before Finish.

  3. Call it from the parent

    Right-click, then Composition → Sub Flow. Set Sub Flow to F_PPECheck and leave Entry Name as Default.

  4. Wire both outcomes

    Leave both blackboard options on. Completed to the rest of the scenario, Failed to an abort path.

    With write-back on, PPEComplete is readable in the parent afterwards, so a later Branch can check it.

When it misbehaves

SymptomCause
The node completed instantly and nothing happenedSub Flow is empty.
The parent hangs on the sub flowThe child has no Finish node.
Child results are missing in the parentWrite Back Blackboard is off.
The child overwrote a parent key you wanted keptWrite-back overwrites by default. Turn it off, or use distinct key names in the child.
The editor hangs on PlayA flow is calling itself, directly or through a cycle.
