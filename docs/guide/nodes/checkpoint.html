Node Reference

Checkpoint Node

Class
USimFlowNode_Checkpoint
Add via
Right-click → Persistence → Checkpoint
Pins
In → Out
Category
Persistence

Use it for: marking a safe resume point, and optionally writing a save when execution reaches it. Nothing blocks: execution passes straight through.

Two things happen when it fires. The component's On Checkpoint Reached event goes out, so your UI can flash "Progress saved" or advance a stage indicator. And the node becomes the anchor for the From Last Checkpoint load mode: a flow loaded that way re-runs from the last checkpoint the trainee passed, instead of restoring a half-finished task.

Fields

USimFlowNode_Checkpoint, Details panel
FieldTypeDefaultMeaning
Checkpoint IdNameNoneIdentifies this checkpoint. Set it.
Auto SaveBoolfalseWrite to a SaveGame slot the moment this node is reached.
Save Slot NameStringemptyOnly shown with Auto Save on. Empty means the component's default slot.
Save User IndexInt0Only shown with Auto Save on.

Leaving Checkpoint Id at None does not break anything. The event still fires and the save still happens. But your UI cannot tell one checkpoint from another, and a debrief cannot report which stage the trainee got to. It costs nothing to name them.

Auto Save on a client does nothing but log. Saving is authority-only.

Auto Save writes synchronously

Never put an auto-saving checkpoint inside a loop

The SaveGame file is written at the moment the node executes, on the game thread. Between stages that is fine. Inside a Loop body it is a disk write every iteration, and it will hitch visibly. Put the checkpoint outside the loop.

Stage boundaries in a long exercise

For a forty-minute exercise the trainee can leave and pick up at the stage they reached.

  1. Configure the component

    Set Default Save Slot Name (say TraineeProgress) and tick Auto Resume From Save On Begin Play.

  2. Choose the load mode

    Set Default Load Mode to From Last Checkpoint.

  3. Place a checkpoint per stage

    Between each stage, right-click then Persistence → Checkpoint. Give each a distinct Checkpoint Id: Stage1Complete, Stage2Complete, and so on.

  4. Turn on auto save

    Tick Auto Save on each, leaving Save Slot Name empty so they share the component's slot. Bind On Checkpoint Reached in your HUD.

    Know what the mode restores. From Last Checkpoint restores the blackboard and the position in the graph. Not a half-finished task.

When it misbehaves

SymptomCause
Loading resumes at the very beginningNo checkpoint had been passed yet, or the flow has none at all. From Last Checkpoint has nothing to anchor to, so use Exact State instead.
Loading restores a half-finished task instead of the stage startThe same setting the other way round. You are on Exact State.
Repeated hitching during a sectionAn auto-saving checkpoint inside a loop.
Nothing saves at all in multiplayerSaving is authority-only. On a client it logs and returns.
The debrief cannot say which stage they reachedCheckpoint Id was left as None.
