Node Reference

Loop Node

Class
USimFlowNode_Loop
Add via
Right-click → Flow Control → Loop
Pins
In, Continue → Loop Body, Completed
Category
Flow Control

Use it for: repeating a section, either a fixed number of times or until a condition passes. Retries, multi-attempt placements, drills that run until the trainee gets it right.

This node needs a return wire

It is the one node whose wiring is not obvious. Loop Body goes out to the section you want to repeat, and the end of that section comes back into Continue. Miss the return wire and the body runs exactly once, then the flow stops.

Fields

USimFlowNode_Loop, Details panel
FieldTypeDefaultMeaning
IterationsInt, min 03How many times to run the body. 0 means "until the break condition passes".
Break ConditionInstanced conditionnullEvaluated before each iteration. Passing exits through Completed.
Max IterationsInt, min 11000Safety valve so a runaway loop cannot hang the game.
Iteration Blackboard KeyNameNoneWrites the current 0-based iteration into this blackboard key.

The last two are advanced settings you can usually leave alone.

The pins

  • In
  • Continue
  • Loop Body
  • Completed

In is the entry, and it resets the iteration counter to zero. Continue is where the body returns to ask for another pass. Loop Body fires once per iteration and Completed fires when the loop is done.

The node stays active while looping and is re-entrant, so arriving at Continue while it is already active is the normal path rather than an error.

How each iteration is decided

Every time In or Continue fires, the node works through this in order.

  1. Move the counter

    In sets it to 0. Continue increments it.

  2. Check Max Iterations

    Hit the cap? Log a warning and exit via Completed.

  3. Check the iteration count

    Iterations greater than 0 and the counter has reached it? Exit via Completed.

  4. Check the break condition

    Set and passing? Exit via Completed.

    The order matters more than it looks. The break condition is checked before the body runs, so a condition already true on entry means the body never runs at all.

  5. Otherwise, run the body

    Write the iteration key if one is set, then fire Loop Body.

Three attempts, or until they get it right

Letting the trainee retry a placement up to three times, stopping early on success.

  1. Add the node

    Right-click, then Flow Control → Loop. Set Iterations to 3.

  2. Set the early exit

    Break Condition to Blackboard Compare: key Placed, operation ==, value type Bool, true.

  3. Expose the attempt number

    Set Iteration Blackboard Key to Attempt so a widget can show "Attempt 2 of 3".

  4. Wire the body

    Loop Body into a Task node running Place Object In Zone. After it, a Set Blackboard Value node writing Placed = true.

  5. Close the loop

    Wire that node's Out back into the Loop's Continue pin, and Completed onward.

When it misbehaves

SymptomCause
The body runs once and the flow stopsContinue is not wired back. This is the classic Loop mistake and worth checking before anything else.
The log says "hit MaxIterations"Iterations is 0 and the break condition never passes, so it ran the full thousand. Fix the condition or set a real count.
The body never runsThe break condition was already true on entry.
The loop stalls partway throughSomething in the body ended without returning to Continue, often a task leaving through an unwired Failed pin. Wire the failure paths back to Continue too, or turn on the Task node's Fallback To Completed.
The attempt counter reads one lowThe iteration key is 0-based. Add 1 for display.
