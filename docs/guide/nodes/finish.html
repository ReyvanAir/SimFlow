Node Reference

Finish Node

Class
USimFlowNode_Finish
Add via
Right-click → Flow Control → Finish
Pins
In, no output
Category
Flow Control

Use it for: ending the run and reporting a result. It is the counterpart to Start, and the only node that actually terminates a flow.

Use as many as the scenario needs: a success ending, a failure ending, an "aborted because the trainee walked out" ending. Each reports its own result to your debrief UI.

The two fields

USimFlowNode_Finish, Details panel
FieldTypeDefaultMeaning
Finish ModeEnumComplete (Success)The result reported for the whole run.
Stop Other BranchesBooltrueStop any parallel branches still running. Leave it on unless you have a reason.

Finish Mode maps straight onto the final run state: Complete (Success) gives Completed, Fail gives Failed, Abort gives Aborted. That state reaches your UI through the component's On Flow Finished delegate, and you can read it at any time with Get Run State.

The flow that never ends

There is no implicit completion in SimFlow

If execution runs out of wiring, the flow sits in Running forever and nothing reports finished. That accounts for most "my flow never ends" reports: either no Finish node on the path that actually executed, or the pin leading to it was never wired.

Pass and fail endings

Reporting success or failure so a debrief screen shows the right result.

  1. Decide the outcome

    After the final task, add a Branch with one case: Score Threshold, >=, 70, labelled Passed.

  2. Add the success ending

    Right-click, then Flow Control → Finish. Set Finish Mode to Complete (Success) and wire the Passed case into it.

  3. Add the failure ending

    A second Finish node with Finish Mode of Fail. Wire the Default pin to it.

    Add a separate Fail node rather than switching the mode at runtime. The mode is authored, not scripted.

  4. Read the result in UI

    In your HUD Blueprint, bind On Flow Finished and switch on the final state.

When it misbehaves

SymptomCause
The flow never reports finishedNo Finish node on the path that ran, or the pin leading to it is unwired.
A branch was cut off mid-taskStop Other Branches working as intended. To let both complete, converge them through a Join in Wait For All mode before finishing.
On Flow Finished reports Completed when the trainee clearly failedThe Finish node they reached still had the default mode on it.
Two endings fired in the same tickThe first to execute ends the run. With Stop Other Branches on, the others never arrive.
