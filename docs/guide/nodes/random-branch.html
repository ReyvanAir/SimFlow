Node Reference

Random Branch Node

Class
USimFlowNode_RandomBranch
Add via
Right-click → Flow Control → Random Branch
Pins
In → Out 0 … Out N
Category
Flow Control

Use it for: varying a scenario between runs. Which fault occurs, which room the task happens in, which distractor appears, so repeat trainees cannot memorise their way through.

Fields

USimFlowNode_RandomBranch, Details panel
FieldTypeDefaultMeaning
Num OutputsInt, 2 to 162How many output pins. Values outside the range are clamped.
WeightsArray of FloatemptyPer-output weights. A missing entry counts as 1.
Avoid RepeatsBoolfalseNever pick the same output twice running within one run.

Weights are relative, not percentages. 45/45/10 and 9/9/2 behave identically, and they do not need to sum to anything in particular.

How the pick is made

  1. Read each weight

    From Weights by index, or 1 if there is no entry. Negative weights clamp to 0.

  2. Apply Avoid Repeats

    If it is on, the previously picked output's weight is forced to 0 for this roll.

  3. Roll

    A weighted roll picks one output.

    Total weight of zero is not an error. The node falls back to a uniform pick across all outputs. Setting every weight to 0 does not break it, it just makes the choice even.

A few consequences follow. A weights array shorter than Num Outputs applies what is listed and defaults the rest to 1; a longer one ignores the extras. A single weight of 0 means that output is never picked, unless all of them are 0. And Avoid Repeats with only two outputs strictly alternates, since there is only ever one remaining option.

Wire every output

An unwired pin here produces an intermittent bug

An unwired output ends execution when it is picked. On a random branch that means a flow which stalls some of the time and works the rest, which is a miserable thing to reproduce. Wire all of them, including the ones you think are unreachable.

Avoid Repeats is per-run

The "last picked" memory lives on the node instance, created when the flow starts. Restarting forgets it, so a fresh run can repeat the previous run's choice. If you need it to survive a restart, persist the last choice in the blackboard and gate on it with a Branch.

Three fault scenarios, one rare

Each run presents one of three faults, with the rare one appearing about a tenth of the time.

  1. Add the node

    Right-click, then Flow Control → Random Branch. Set Num Outputs to 3.

  2. Weight the outcomes

    Under Weights, add three entries: 45, 45, 10.

  3. Stop immediate repeats

    Tick Avoid Repeats so the same fault does not come up twice running.

  4. Wire all three

    Each output to its scenario, converging them with a Join if they share an ending.

When it misbehaves

SymptomCause
One branch never happensIts weight is 0, or Weights has fewer entries than you think and the indexing is off by one. Weights index from 0.
The flow sometimes just stopsAn unwired output pin got picked.
Avoid Repeats did not prevent a repeat across runsIt is per-instance and resets on restart.
Every outcome is equally likely despite the weightsThe weights total zero, so the node fell back to a uniform pick.
